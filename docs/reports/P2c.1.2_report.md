# P2c.1.2 報告：「気付いている敵」の判定を揃える

仕様「P2c.1.2：『気付いている敵』の判定を揃える（確定）」を実装した。

## 完了基準の確認

| 基準 | 結果 |
| --- | --- |
| Unity 6.3 LTS（6000.3.11f1）でテストが全て通る | EditMode 277件全て通過 |
| .NET でテストが全て通る | 267件全て通過（通し実行の表とログのハッシュを含む） |

| 通し実行の表と理由 | 下 |

## 変わったこと

- **「気付いている」の判定を1か所に**（`SimulationSight.cs`）
  - `Aware(c, e)`：視線が通るか、接触の距離（矩形の隙間 50m 以内。`InFireContact`）。撃つための視線（`SightForFire`）と P2c.1.1 の接敵中（`EnemyInContact`）も、この判定を使うようにした
  - 点で見る場合の `InContactAt(p, facing, 敵の矩形)`：点 p に向き facing で置いた中隊の矩形が、敵の矩形と接触の距離か。物陰の候補と退路の見積もりで使う
- **揃えた5つ**
  1. P1d の向き直りの「正面の弧が空いているか」（`FrontArcOccupied`）：視線が要る性格（慎重・冷静）は、気付いている敵だけを数える（接触の距離の敵が正面にいれば空いていない）
  2. P2c.1 の自律の向き（`FrontArcHasVisibleEnemy`・`NearestVisibleEnemy`）：正面の弧の敵、向く相手とも、気付いている敵
  3. P2c の物陰の「今の目標が見え続ける所」（`CanShootFrom`）：候補の点から、射程内で視線が通るか、今の向きで置いた矩形が接触の距離なら「撃てる」
  4. 露出の地図（`BuildExposure`）：敵の矩形から 50m 以内のマス（マスの中心までの距離）は、視線を問わず射界に数える
  5. 退路の見積もり（`EstimateEscape`）：逃げる各刻みで、視線が通るマスにいるか、逃げる向きで置いた矩形が敵の矩形と接触の距離なら、撃ってくる敵に数える
- **揃えないもの**：P1g の見える位置を探す候補の点（`EngageableFrom`）は今のまま
- 地図の写しの照合（`Visibility.Exposure`。map_reference.py と同じ露出の地図）は変えていない。Sim の露出の地図（`ExposureFor`）だけを変えた

### テスト（`P2c12Tests`、6件）

どの場面も、稜線（高さ 30m）を挟んで隙間 40m にいる、見えない敵を「気付いている」として扱うことを確かめる。

1. 東から脇を撃たれても、正面（北）の接触の距離に気付いている敵がいれば、向き直らない（冷静）
2. 撃てる目標がない東向きの中隊が、接触の距離の北の敵の方を向く
3. 正面（北）の接触の距離に気付いている敵がいれば、東 500m の見える敵の方へ向き直らない
4. 物陰の候補の点：東隣の点は見えないが接触の距離なので「撃てる」。南へ 75m 下がった点は「撃てない」
5. 露出の地図：敵の矩形から 25m のマスは、敵から見えなくても射界。75m のマスは射界でない
6. 退路の見積もり：接触の距離を 0 にした値と比べ、南へ逃げる方位で、逃げ始めの接触の距離の間だけ撃たれる（0 → 正）。どの方位も小さくならない

### 大きく変わった作戦と理由

- 近い拘束では、拘束役 B2 が稜線の陰で R1 と接触の距離にいる。P2c.1.1 までは、視線の要る冷静の R1 は、正面の接触の距離の B2 を「正面にいない」と数えていた。そのため、北から回り込んで脇を撃ってきた B1 の方へ、練度の遅れの後に向き直り、B1 の側面攻撃を正面で受け止めていた
- P2c.1.2 では、正面の B2 に気付いているので「正面は空いていない」として向き直らず、B1 に脇を撃たれ続ける。経過の表で、R1 の壊走は 19/20・58.5分 → 16/20・33.4分と大きく早まった（R1 の向き直り自体は 20/20 のままで、21.1分 → 26.2分と遅れた）

## 迷った点と、自分で決めた点

1. **物陰の候補（3）は、今の規則では効く場面がない**：接触の距離（隙間 50m 以内）の点は、経路で敵を避けるマス（敵の矩形から約 113m）に必ず入るので、物陰の候補から先に外れる。判定は仕様どおり入れ、単体テストは判定の関数（`CanShootFrom`）を直接確かめた。切り分けでも「物陰だけ」の版は「なし」と同じ値
2. **露出の地図の「敵の矩形から接触の距離のマス」**：マスの中心と敵の矩形の距離が 50m 以内のマス、とした（マスに置く中隊の大きさは考えない。伝令は点なので、そのまま当てはまる）。敵の矩形は、見える範囲を作った時点の位置と今の向き。中隊の経路では、このマスは敵の周りの通れないマスに含まれるので効かない。効くのは伝令の経路と倒れる場所
3. **退路の見積もりの矩形**：逃げる中隊の矩形は、逃げる向き（壊走中は進む方を向く）で置く。敵は動かないものとして今の矩形。隙間の計算は重いので、中心どうしが届きうる距離（両方の矩形の半対角＋50m）のときだけ行う
4. **地図の写しの照合**：map_reference.py と同じ露出の地図（`Visibility.Exposure`。地図の照合のテストに使う）は変えていない。Sim の露出の地図だけを変えた
5. **自律の向き（2）**：撃てる目標がある間は使わないので、接触の敵（撃てる目標になる）を数える効きは、兵がいない敵など、ほぼ起きない場面に限られる。切り分けでも「自律の向きだけ」の版は「なし」と同じ値
