# P2c.2 設計報告：意見具申

仕様「P2c.2：意見具申（確定）」の実装の設計。返答があるまで実装には入らない。

## 1. 中隊の伝令の持ち方（P2a の伝令との共通化）

- 新しい種類 `Courier`（中隊の伝令）を作り、本部の伝令（`Runner`）とは別の一覧（`Simulation.Couriers`）に持つ
  - 本部の伝令の番号（ログの `runner`）がずれないように、一覧を分ける
  - 状態：準備中 → 本部へ向かう → 届いた／倒れた（片道。戻らない）
  - 持つもの：陣営、中隊、出した時刻、位置、経路（点の列・添字・次に引き直す時刻）、載せた具申（下の `Dispatch` の列）
- **動きは共通にする**：本部の伝令の動き（`MoveRunner`：経路を 10秒ごとに引き直し、マスの移動倍率で進む）を、両方が持つ共通の土台（位置・経路・添字・引き直しの時刻）に対して動かす形に直す。速さ（秒速 3m）・経路の重み（射界 ×3.0、敵の矩形のマスは通らない）・川の渡り方・射界での喪失（毎秒 0.3%）は本部の伝令の値（`runners.*`）を使い直す
- 準備は 10秒（新しい値）。出発は中隊のその時の位置、行き先は本部（動かない）
- **戦闘の結果を変えないための注意**
  - 喪失の乱数は、戦闘とも本部の伝令とも別の流れ（新しい流れの番号）から引く
  - 中隊の伝令の経路と喪失の判定では、Sim の使い回し（露出の地図・見える範囲）を**作らない**。今の Sim は露出の地図を「その10秒の間に初めて要った時点」で作り（P2c.1.2 で敵の向きも使う）、中隊の経路もそれを使う。中隊の伝令が先に作ってしまうと、作る時点がずれて中隊の経路が変わりうる。そこで、中隊の伝令は「あれば使い、なければその場で作って捨てる」口（今の `WithoutCaching`・`PeekExposure` と同じ考え）だけを使う
- 判断枠は数えない。1中隊に同時2人まで（3人目の分は出さずに捨てる。古い方を残す）
- 赤の中隊は送らない

## 2. 報告の判定の置き場所

- 新しいファイル `SimulationDispatch.cs`。中隊ごとに「具申の箱」（送る前の具申の列、まとめの時計、判定の覚え）を持つ
- 判定は2通り。どちらも戦闘の状態を一切変えない（読むだけ。具申の列に足すだけ）
  - **その場で足す**：規則の中で起きたことを、その場で具申の列に足す（1行の呼び出し）
    - 目標崩壊・追撃の可否：`OnAttackTargetBroken`
    - 隣の崩壊：`Rout`（300m 以内の青の味方に足す）
    - 陣地完成：`CompleteEntrenchment`
    - 宣言：P2c の宣言を出している所（`LogIndependent` の呼び出し元）
  - **刻みの最後に見る**：`Step` の最後（`UpdateAutonomy` の後）の `UpdateDispatches` で、前の刻みからの変わり目を見る
    - 命令を終えた：命令待ち（`AwaitingOrders`）が偽→真になった時。会戦の初めは全て命令待ちなので、そこからの変わり目だけ（P2b.1 の表示と同じ）
    - 命令を請う：命令待ちが 5分続いた時、以後 10分ごと。命令待ちでなくなったら時計を戻す
    - 敵発見：気付いている（`Aware`）指揮下の敵が 600m 以内に初めて入った時（中隊ごと・敵ごとに一度だけ）。まだ見つけていない敵だけを毎刻み調べる
    - 損害大：前の「損害大」から兵力の 20%（慎重は 10%）を新たに失った時。初めの兵力に対する割合で数える
    - 攻撃頓挫：動揺で停止中（`ShakenHalt`）が偽→真になった時
    - 後退の許可：動揺していて（慎重は士気 60 未満）、かつこの刻みに撃たれた時
- **送った時点の中隊の様子**：具申を列に足した時ではなく、伝令が出る時に添える（伝令に載る時点の様子）。兵力の割合・士気・状態・位置・今の段（「第2段 攻撃 R1」）
- **同じ要請を繰り返さない**（「状況が変わるまで」の読み）
  - 後退の許可：送った後は、条件が外れる（士気がしきい値を越える、または 10秒撃たれない）まで送らない
  - 追撃の可否：目標が崩れるたびに1回（崩れた目標ごとに新しい状況）
  - 命令を請う：10分ごとに繰り返す（例外）

## 3. まとめの間隔と宣言の扱い

- 報告・要請：同じ中隊の前の伝令（報告・要請を載せたもの）が出てから 60秒経っていなければ、列にためて 60秒の時点で1人の伝令にまとめて出す。60秒以上あいていれば、すぐ出す
- 宣言：まとめを待たずに、その刻みに1人の伝令で出す。そのとき列にたまっている報告・要請も一緒に載せる（どうせ走るので）。60秒の時計はそこから数え直す
- 同時2人を越える分：出す時点で2人が走っていれば、その伝令の分は捨てる（ログに `courier_dropped`）。宣言も同じ

## 4. 性格の差

- 慎重：後退の許可は士気 60 未満から。損害大は 10% ごと（裁量によらない）
- 猪突・機敏（任せる）：独断できる場面では宣言を送る（要請は送らない）
  - 猪突が「確保」で崩れた目標を独断で追う → 「追撃の可否」ではなく宣言「追撃に移る」
  - 機敏は「確保」で追う独断がないので、追撃の可否を送る（仕様の表の「冷静・慎重・機敏」）
- 厳命の猪突・機敏は冷静と同じ

## 5. 表示（具申の箱の画面と操作）

- **出来事の欄**：伝令が本部に着いた時に、載せた具申ごとに1行
  - 「[T+12:30 発] B2 目標崩壊（R1）」「[T+12:30 発] B2 追撃の可否を問う（R1）」「[T+12:30 発] B3（猪突）追撃に移る（R1）」
  - 行の終わりに、出た時点の様子「（兵力 82%・士気 55・動揺）」
  - 要請は目立つ色（水色の太字）。宣言は今の独断の色（橙）
- **具申の箱**：左パネルの中隊の一覧の下に「具申（3）」の欄
  - 届いた要請の行：「[T+12:30 発] B2 追撃の可否（R1）［許可］［消す］」
  - ［許可］：その中隊を選び、起案の欄に命令書を作る（発令はプレイヤー）
    - 追撃の可否：第1段に「R1 を攻撃（範囲の指定なし・崩れたら追撃）」
    - 後退の許可：命令の種類を「後退」にして、行き先の地図のクリックを待つ（行き先はプレイヤーが決める）
    - 命令を請う：白紙の起案を開く
    - すでに起案があれば、置き換える前に確かめない（今の起案を捨てて作り直す）か、出さないかは迷った点 4
  - ［消す］：その行を箱から消す
  - 古くなった要請（その要請が出た後に、その中隊へ新しい命令書を出した）は薄くする
- **中隊の伝令**：中隊から本部への緑の点線と、動く緑の点（本部の伝令は黄・水色のまま）
- **左パネル**：青の中隊ごとに「最後の報告 T+08:10」（その中隊の伝令が最後に本部に着いた時刻。まだなければ「—」）
- **自動一時停止**：上部の「自動一時停止」の隣に「要請で止める：切」の切り替え（初めは切）。入なら、要請が届いた刻みに止めて、理由に「B2 追撃の可否」
- P2c の宣言の即座の表示（出来事の欄・駒の上の文字）は、伝令が届いた時の表示に置き換える。駒の行動の印（独断中の橙）は今どおり

## 6. 戦闘の結果を変えないことの確かめ方

- 中隊の伝令は情報だけ。具申を足す・伝令を動かす処理は、中隊・射撃・士気・命令・Sim の使い回し（露出の地図など）を変えない（1 の注意）
- ログには新しい行（`courier_sent`・`courier_lost`・`courier_dropped`・`courier_delivered`）だけが増える
- **確かめる手段**
  - 速いテスト：シナリオA の作戦を数通り（ステージ1・2、短い時間）、中隊の伝令を止めた値（同時の数 0）と、入れた値で回し、新しい行を除いたログが1文字も違わないこと
  - 通し実行のログのハッシュ（`ScenarioLogHashTests`）に、新しい行を除いたハッシュを出す口を足し、P2c.1.2 のハッシュ（報告に出した 36通り）と一致を確かめるテストを足す。時間がかかるので、Takeru がローカルで回す
  - 通し実行の表（勝率・損害・崩れ方）は P2c.1.2 と完全に一致するはず。回し方（コマンドと所要の目安）を報告に書く

## 7. パラメータのキー（提案）

`sim_params.json` に新しい節 `couriers` を足す。速さ・喪失・経路の重み・引き直しは `runners.*` を使い直す。

```json
"couriers": {
  "_note": "P2c.2 の中隊の伝令（意見具申）。速さ・喪失・経路は runners の値を使う。heavy_loss_step は初めの兵力に対する割合。retreat_ask_morale は慎重が未満、ほかは以下",
  "prep_sec": 10,
  "max_out_per_company": 2,
  "batch_sec": 60,
  "discover_radius_m": 600,
  "heavy_loss_step": { "cautious": 0.10, "calm": 0.20, "agile": 0.20, "reckless": 0.20 },
  "neighbor_rout_radius_m": 300,
  "ask_orders_after_sec": 300,
  "ask_orders_repeat_sec": 600,
  "retreat_ask_morale": { "cautious": 60, "calm": 50, "agile": 50, "reckless": 50 },
  "retreat_ask_quiet_sec": 10
}
```

- `retreat_ask_quiet_sec`：「撃たれている」が途切れたとみなす秒数（同じ要請を繰り返さないための、状況が変わった判定）。P2c の `autonomy.cover_fire_gap_sec` と同じ 10秒
- `neighbor_rout_radius_m`：今の `morale.neighbor_rout_radius_m`（壊走の連鎖の 300m）と同じ値だが、意味が違うので分けた

## 8. テスト

- 単体テスト（手引きの一覧）：報告7種・要請3種・宣言が仕様の時に送られる／伝令が着いて届く、倒れたら届かない（喪失を 1 にした値で）／判断枠を使わない／60秒のまとめ、宣言は即座／同じ要請を繰り返さない／命令を請うが 5分・10分ごと／慎重・猪突・機敏の差／追撃の可否の［許可］で、追撃の攻撃の命令書が起案の欄にできる（起案を作る関数を View の外の純 C# に置いて試す）
- 戦闘の結果を変えない：6 の速いテスト
- 長い計算（通し実行、ログのハッシュの一致）は回さず、回し方を報告に書く

## 9. 迷った点（素直な解釈を提案に入れた）

1. **宣言の伝令に、たまっている報告・要請を載せるか**：載せる（どうせ走るので。60秒の時計はそこから数え直す）
2. **「命令を終えた」と「命令を請う」の始まり**：会戦の初めの命令待ちは「命令を終えた」にしない。命令を請うの 5分は、会戦の初めから数える（命令書を受けないまま 5分経てば送る）
3. **後退の許可の「撃たれている時」**：その刻みに撃たれた（射撃の目標になった）とき。送った後は、士気がしきい値を越えるか 10秒撃たれなくなるまで送らない
4. **［許可］のときに起案がすでにあれば**：今の起案を捨てて作り直す（許可は「この案で起案する」という操作なので）。捨てる前に確かめはしない
5. **敵発見の「600m 以内に初めて入った」**：中隊ごと・敵ごとに一度だけ。会戦の初めにすでに 600m 以内で気付いている敵は、最初の刻みに送る
6. **損害大の数え方**：初めの兵力に対する割合（150人の 20% = 30人を新たに失うごと）
7. **追撃の可否の条件**：目標が壊走中（追えるとき）だけ。降伏・離脱・再集結で崩れたときは送らない（目標崩壊の報告だけ）
8. **崩した目標が独断の攻撃の目標でも**：目標崩壊の報告は送る（独断の続きは宣言で送る）
9. **宣言にする独断**：P2c の宣言（猪突の追撃・続けての攻撃、機敏の回り込み、慎重の独断の後退、慎重の「追撃せず」）。「独断の限度で停止」は、命令待ちになるので「命令を終えた」の報告で知らせる
10. **P2c の自律行動の出来事（物陰へ・浅い掩体・陣地に入る）**：今どおり出来事の欄に即座に出す（仕様が伝令に載せ替えるとしているのは宣言だけ）。霧は P2d
11. **届いた具申を Sim が持つか**：Sim は届いた具申の列（読み取り専用）を持つ。箱の［消す］や薄くする判定は View が持つ
