# P1a 設計報告：地図のロジック（着手前）

依頼文に従い、実装に入る前に設計をまとめた。**返答があるまで実装には入らない。** 仕様は `docs/spec.md` の「P1 詳細仕様」と、P0.2 で確定した包囲の細則を前提にしている。

## 1. 地図の持ち方

新しいクラス `TerrainMap` を `Sim` アセンブリに置く（`Battalion.Sim`、UnityEngine 非依存のまま）。

| 項目 | 持ち方 |
| --- | --- |
| 格子 | 幅・高さ・1マスの長さ（50m）と原点。内部の添字は `[j * 幅 + i]`、`j = 0` が南。ファイルの行は北が先なので、読み込み時に上下を反転する（`map_reference.py` と同じ） |
| 基本の地形 | 文字の配列（`.` `F` `V` `W` `B` `S` `T`）。会戦中は変えない |
| 会戦中に変わる層 | 別の配列（なし／構築した塹壕／砲撃痕 `C`）。引くときは「変わる層に値があればそれ、なければ基本の地形」。川・橋・浅瀬のマスには載せない |
| 標高 | double の配列。視線用の双線形補間（マス中心の値から）と、マス単位の値の両方を引ける |
| 地形の表 | 移動倍率・被弾倍率・視線を遮る重み（森 1.0、村 0.5）を文字ごとの表で持つ。値は `map_reference.py` と仕様の地形の表と同じ |

- シナリオの情報（初期配置、`reserve_script`、村や橋のマス、制限時間）は `MapScenario` に分ける。読み込みは既存の自前 JSON パーサーを使う
- 地図ファイルにない情報（中隊の性格と練度。第1 慎重・通常、第2 冷静・通常、第3 猪突・古参、第4 機敏・通常、敵は全て通常）は、仕様の兵力の表から C# のシナリオ定義に持たせる。地図ファイルは変更しない
- **`Simulation` は常に地図を持つ。** 今の `MapBounds` は地図の範囲に置き換える。S1〜S6 は「全て平地の地図」の上で回す。S1〜S6 の座標は負の値を含む（x −1200〜1800）ので、地図に原点を持たせ、平地の地図は原点（−1200, −850）・60×40マスで作る。これで S1〜S6 の配置と、壊走したときに会戦から離脱する範囲は P0 と同じになる。全部隊が 400m 以内にいて全て見えるので、射撃と退路の見積もりの結果は変わらない見込み（テストで確かめる）

## 2. 視線と経路探索の置き場所

どちらも `Sim` アセンブリの、状態を持たない計算として置く。乱数は使わない。

| クラス | 役割 |
| --- | --- |
| `LineOfSight` | `Check(map, from, to)` → 見えるか／理由（`range`・`ridge`・`cover`・`clear`）。`map_reference.py` の `los` と同じ手順（10m 刻み、両端を除く、目の高さ+2m、森・村の重み付き距離が100mを超えたら遮る、視界距離 800m×(1+0.1×高低差÷10m)） |
| `ExposureMap` | 陣営ごとの「そのマスの中心が、400m 以内の敵から見えているか」の格子。視線は敵の中心からマスの中心へ引く（リファレンスと同じ向き） |
| `PathFinder` | 8近傍の A*。1歩のコスト＝距離÷移動倍率＋脅威の重み×露出×50。斜めは通れないマスの角を切らない。戻り値はマスの列とコスト。一直線に並ぶ点を間引いたうえで、最後に目的地そのものを足す |

- **A* の同点の扱いはリファレンスに合わせる。** 優先度付きキューは（f, g, i, j）の辞書順で取り出し、近傍は（di, dj）を −1, 0, 1 の順に調べる。取り出したときに g が古いものは捨て、目的地を取り出した時点で止める。これで検証ケースの経路がリファレンスとマス単位で一致することを狙う（完了基準は経路長±5%、露出±71m）
- 目的地が通れないマス（川）にある場合は、目的地に最も近い通れるマスへずらす。出発点が通れないマスにある場合（押し離しで川へ寄った等）は、そこから出る1歩だけを許す

## 3. 露出の地図の更新方法

- 陣営ごとに1枚ずつ（青から見た赤の射界、赤から見た青の射界）。数える敵は盤上にいる指揮下（正常・動揺）の中隊。壊走中・再集結中の中隊は撃たないので数えない
- 10秒ごと（ゲーム内時間、刻み数で決める）に作り直す。会戦の開始時にも作る
- 1回の作り直しは、敵1個中隊あたり 400m 以内のマス（約200マス）×視線1本（最大40点）。7個中隊で数万回の計算なので、毎回作り直してよい
- 経路は、命令を受けたときと、その後30秒ごと（中隊ごとに、前回引いた時刻から30秒）に、その時点の露出の地図で引き直す

## 4. 命令の状態の持ち方

`Order`（命令オブジェクト）は種類を足す。

| 命令 | 命令オブジェクトの中身 |
| --- | --- |
| 前進 | 目的地、到着後の向き（任意） |
| 攻撃 | 目標の敵中隊、方向（正面／側面／背面／指定なし） |
| 後退 | 目的地、到着後の向き（任意） |
| 保持 | 向き（任意） |
| 拘束 | 目標の敵中隊 |
| 陣地構築 | なし |

`Company` には、命令を実行するための状態を持たせる。

| 状態 | 内容 |
| --- | --- |
| 経路 | 通る点の列と、次に引き直す時刻 |
| 移動の仕方 | 通常（進行方向を向いて進む）／後ろ向き（後退で目的地が背後の弧にあるとき） |
| 攻撃 | 選んだ側（左／右。側面のとき）、発起点、次に発起点を更新する時刻、発起点に着いたか |
| 陣地構築 | 進捗（秒）。動いたら 0 に戻す |
| 動いたか | その刻みに位置が変わったか（塹壕の被弾倍率と陣地構築の判定に使う） |

挙動の要点：

- **前進**：経路に沿って進む。P0 と同じく、各区間の向きへ旋回し終えてから進む（毎秒6°）。速度は中隊の中心があるマスの移動倍率×拘束の×0.5
- **攻撃**：発起点は「敵の中心からその方向へ250m」。方向の基準は敵の向き（正面＝敵の向きの方向、背面＝逆、側面＝左右）。側面は左右それぞれへの経路を引いて、コストの小さい側を選ぶ。方向の指定がなければ正面。ただし機敏は、側面の経路コストが正面の1.5倍以下なら側面を選ぶ。発起点は30秒ごとに敵の今の位置と向きで計算し直す（選んだ側は変えない）。着いたら敵に正面を向けて撃ち続ける。敵が動いて発起点が離れたら、また動く
- **後退**：目的地が背後の弧（向きから120°より後ろ）にあれば、向きを変えずに経路に沿って後ろ向きに下がる（×0.6）。判定は命令を受けたときと、経路を引き直すときに行う。それ以外は前進と同じ。離脱のルール（P0）はそのまま
- **保持**：その場で指定の向きを保つ
- **拘束**：その場で、目標の敵に正面を向けて撃ち続ける。射撃の目標は、目標の敵が射程内で見えていればその敵、そうでなければ通常の目標選択
- **陣地構築**：その場で動かずに10分で完成。途中は被弾倍率が地形の値から 0.3 へ進捗に比例して近づく。完成すると、中心のマスと、向きに直交する方向の左右2マスずつ（計5マス）が変わる層で塹壕になる
- **動揺**：前進・攻撃を拒む（保持になる）。P0 と同じく、動揺に入った時点で前進・攻撃をやめて保持する

射撃と地形：

- 射撃の目標は、射程内で視線が通る敵に限る（目標選択の規則は P0 と同じ）
- 被弾倍率は撃たれる側の中心のマスで決める。塹壕（基本の地形・構築した塹壕とも）の 0.3 は、その刻みに動いていない中隊にだけ効く。動いている中隊は平地と同じ 1.0
- 移動倍率は中隊の中心のマスで決める。川は通れない

## 5. 重なり禁止の解き方

- **初期配置**：味方の中心どうしが200m未満なら、シナリオの読み込みで例外にする（ステージ1・2 とも満たしている。B2 と B4 がちょうど200m）
- **目的地が近すぎる場合**：命令を受けたときに、他の味方（止まっている中隊はその位置、動いている中隊はその目的地）から200m未満なら、目的地を中心に 50m 刻みで外へ広げた輪の上（16方位）を調べ、条件を満たす通れる点のうち元の目的地に最も近い点へずらす
- **移動中に近づきすぎた場合**：毎刻み、移動の後に、200m未満の味方の組を ID の小さい順に1回ずつ調べて押し離す（概算シミュレーションと同じ）。両方が動いていれば半分ずつ、片方だけが動いていれば動いている方だけを押す（陣地にいる中隊が押し出されて陣地構築の進捗や塹壕の効果を失わないように）。押した先が通れないマスなら押さない
- 壊走中・再集結中の中隊と敵中隊は対象外

## 6. 予備隊の台本と P0.2 の続き

- **予備隊の台本**：毎刻み、引き金の円（`trigger_center` から `trigger_radius_m`）の中に指揮下の青の中隊の中心があれば一度だけ発動する。R3 は、円の中にいる青の中隊のうち R3 に最も近いものに、R3 の側の側面から攻撃する（方向を「側面」、側を R3 の側に固定した攻撃命令）。R3 の経路の脅威の重みは 0（概算シミュレーションと同じ。敵の性格はスコープ外）。R1・R2 は保持（向きを変えない）
- **退路の見積もりに視線を足す**（P0.2 の回答4）：見積もりの各点で、その点が敵から見えている場合だけ、その敵を数える。点ごとに視線を引くと重い（敵4個中隊なら1回の見積もりで 16方位×277点×4＝約1.8万本、標高の参照は最大約70万回）ので、敵ごとに「400m 以内の各マスの中心が見えるか」を露出の地図と同じ間隔（10秒）で作っておき、見積もりの点はその点のマスで引く。地形による被弾倍率は入れない
- **籠城**：中隊の中心のマスが村、または塹壕（基本の地形・構築した塹壕）なら `Fortified`。塹壕の被弾倍率と違い、動いているかどうかは問わない（概算シミュレーションと同じ）

## 7. 5つの作戦の通し実行

- `battle_sketch_v3.py` の `plans` を、同じ時刻・目的地・向きの前進命令として C# に写す。各ステージ5作戦×シード1〜20
- 勝ちの判定は概算シミュレーションと同じ：90分の時点で、村のマスに指揮下の青の中隊がいて、村の中心（1975, 1000）から250m 以内に指揮下の赤の中隊がいない。または赤が全て盤上から消え、青が残っている
- 報告する項目：勝率、青の損害率、崩れた（壊走・降伏・離脱した）青と赤の中隊数、降伏させた赤の中隊数、終了時刻の中央値。概算の結果と並べる
- 概算シミュレーションとの違いで、結果がずれうる点（あらかじめ挙げておく）：旋回の速さ（概算は即座に向く）、再集結（概算はなし）、陣地構築、射撃の目標の視線（概算は2秒ごとにまとめて判定）、動揺した中隊の扱い（概算は士気50以下で止まるだけ）

## 判断を仰ぎたい点

もっとも素直と思う案を添えた。

1. **退路の見積もりの視線をマス単位で近似してよいか**（上の6）。点ごとに引くこともできるが、見積もり1回が数ミリ秒の見込みで、5作戦×20回×2ステージの通し実行が十数分以上に延びる。マス単位なら、逃げる点がマスの中を通る間は同じ判定になる（最大で約35m のずれ）
2. **退路の見積もりで、川と地図の端をどう扱うか。** 概算シミュレーションは「川に突き当たる方位は逃げられない」「地図の外に出られる方位は、出るまでの損害で打ち切る」としているが、仕様と参照実装にはない。案：概算と同じにする。壊走した中隊が川へ逃げて止まる、を避けられる
3. **壊走中に川に突き当たった場合**：案：その刻みは動かない（概算と同じ）。5秒後の見積もりで別の方位に変わる
4. **陣地構築で塹壕にするマス**：案：平地と砲撃痕のマスだけを塹壕にする。森・村・川・橋・浅瀬は変えない（村や森を塹壕にすると視線の遮りが消えるため）。向きに直交する左右は、向きを8方位に丸めて決める
5. **押し離しの片寄せ**（上の5）：概算は常に半分ずつ押しているが、止まっている中隊は押さない案にした
6. **R3 の経路の脅威の重み**：案は 0（概算と同じ）。冷静（1.0）にする手もある
7. **勝ちの判定**：案は概算と同じ。仕様の「90分の時点で確保していること」を、この定義で読んでよいか
8. **S1〜S6 を平地の地図で回すこと**：原点をずらした平地の地図に載せる案。地図なし（P0 の挙動）を残す方法もあるが、コードの分岐が増える
