# P1e 設計報告（着手前）

対象：docs/spec.md「P1e：行動と命令の改善（確定）」の1〜6。返答をいただくまで実装しません。

## 1. 隊列の超越

**経路**
- `FindPath` で、止まっている指揮下の味方の中心から 200m 未満のマスを「通れない」から「距離のコスト ×3」に変える。
  - `PathFinder.Find` に、マスごとのコストの倍率（`double[]`、null なら全て 1）を足す。
  - 掛けるのは「距離÷移動倍率」の項だけ。露出の項には掛けない。
  - 倍率は 1 以上なので、A* の下限の見積もり（直線距離）はそのまま使える。
- 引き方の順番：
  1. 敵の 110m を避け、味方の周りは高コストにして引く。
  2. 届かなければ、届くところまでの経路を引く。
  - P1d にあった「味方の周りを避けると届かないので、敵だけを避けて引き直す」段は要らなくなるので、なくす。
- 目的地をずらす規則（AdjustDestination：味方から 200m 未満の目的地はずらす）は変えない。抜けた先で味方に重なって止まることはない。

**抜けている間**
- 次の両方を満たす間を「超越中」とする（迷った点1）。
  - 止まっている味方 f と中心どうしが 200m 未満。
  - 自分の残りの経路が f の 200m の圏を通る、または自分の矩形が f の矩形と重なっている。
- 超越中は、f との間で `KeepFriendlySpacing` の押し離しをしない。
- 速さ ×0.5 を掛けるのは、仕様のとおり矩形が重なっている間だけ（`UnitRect.Overlap`）。
- 判定は Move の始めに全中隊まとめて行う。中隊を処理する順番で結果が変わらないようにするため。

**P1d の規則との関係**
- 敵を避ける規則（矩形から 110m のマスは通らない、隙間 10m の手前で止まる）は変えない。味方の中は抜けられるが、敵の中は抜けられない。
- 壊走中のすり抜け（隊形の乱れ）は今のまま。対象は壊走中の中隊だけで、超越する指揮下の中隊は対象外。

## 2. 動くときの向き

**接敵の判定**
- 400m 以内に、視線の通る指揮下の敵がいれば「接敵中」とする。壊走中・再集結中・降伏した敵は数えない。
- Move の始めに全中隊まとめて判定する。
- 視線の判定は今の `LineOfSight.Visible` を使う。

**FollowPath の新しい規則**（壊走は対象外で、今のまま）
- 接敵中：向きを変えない。目的地（今向かっている経路点）への方角を、今の向きと比べる。
  - ±60° 以内（正面の弧）：前進。今の速さのまま。
  - 60〜120°（横）：横歩き。速さ ×0.5。
  - 120° を超える（背後の弧）：後ろ向き。速さ ×0.6。
  - 弧の境目は fire の `front_arc_deg`（60）と `flank_arc_deg`（120）をそのまま使う。
- 接敵していないとき：経路の区間の方角へ旋回しながら進む（止まらない）。向きと進む方角の差が 20° を超える間は、速さ ×0.7。
- 着いた後：向きの指定があればその向きへ旋回する（今と同じ）。
  - 攻撃は、着いた後に目標を向く（P1d と同じ）。
  - 拘束は、着いた後に目標を向く（P1d と同じ）。
- 途中で接敵の状態が変わったら、その刻みから規則を切り替える。
  - 旋回の途中で接敵したら、そこで旋回をやめて、その向きのまま動く。
- 速さの倍率は全て掛け合わせる：地形 × 拘束されている（0.5）× 横歩き・後ろ向き × 超越 × 旋回中。

**命令ごとの扱い**

| 命令 | 接敵中 | 接敵していない |
|---|---|---|
| 前進・目的地のある陣地構築 | 向きを変えずに、前進・横歩き・後ろ向き | 旋回しながら進む |
| 攻撃（発起点まで）・拘束（詰めるまで） | 同上 | 同上 |
| 追撃 | 同上（追っている壊走中の敵は接敵に数えない） | 同上 |
| 後退 | 同上（背後の弧なら後ろ向き ×0.6） | **今のまま**：背後の弧なら後ろ向き ×0.6、それ以外は旋回しながら進む（迷った点2） |
| 壊走 | 今のまま | 今のまま |

**表示のための状態**
- `Company.MoveStyle`（なし／前進／横歩き／後ろ向き／旋回中）を毎刻み更新する。View の印に使う。ログには出さない。

## 3. 拘束の距離

- `enum PinRange { Far, Near }` を足す。`Order.Pin(companyId, targetId, PinRange range = PinRange.Far)` とする。
- 遠い：350m（今いる方角の 350m の点。すでに 350m 以内ならその場）。近い：125m（P1d と同じ）。
  - 30秒ごとに点を計算し直す、50m 以上ずれたら動き直す、動揺したら詰めない、の規則は両方で共通。距離だけを替える。
- 足止めの効果（pinning の 150m）は今のまま。
  - 遠い拘束は 150m の外なので、足止めは掛からない。
  - 撃ち合いの射程（400m）の内側なので、撃ち合いはする。
  - 慎重・冷静の向き直りの条件（正面 400m 以内に敵）を満たすので、向き直りを防げる。どれも今の規則から自然にそうなる。

## 4. 攻撃の方向を「攻める方角」で指定する

**Order の形**
- `Order.Attack(companyId, targetId, AttackAspect range = None, double? bearingRad = null, AttackOnBreak onBreak = Secure)`
  - `bearingRad`：地図の方角での指定（目標の中心から見た方角）。指定すると range より優先する。
  - P1d の `flankSide` と `lockSide` はなくす。地図の方角で指定した攻撃が、側を固定した攻撃に当たる。

**発起点**
- 目標の中心から、方角 θ に 250m の点。`JumpOff(tgt, θ)` に一本化する。
- 正面・側面・背面は、θ と目標の向きの差で結果として決まる。ログの `attack_plan` には `bearing`（度）と、結果の `aspect` を出す。

**方角の選び方**
- 「今の方角」：目標の中心から見た自分の中心の方角。
- 地図の方角での指定：θ をそのまま使い、着くまで変えない。
- 範囲での指定（F・S・B）：目標の向きを基準にした角度 a で判定する。
  - 範囲：正面は |a| ≤ 60°、側面は 60° ≤ |a| ≤ 120°、背面は |a| ≥ 120°。
  - 今の方角が範囲に入っていれば、今の方角を使う。
  - 入っていなければ、範囲の端から 10° 内側の方角のうち、今の方角に最も近いものを使う。
    - 側面：±70° と ±110° の4つが候補。
    - 正面：±50° が候補。
    - 背面：±130° が候補。
  - 角度の差が同じ候補が2つあるとき（真正面から側面を指定した等）は、経路コストの安い方を使う。届かない方は選ばない。
- 指定なし：今の方角を使う。
  - 機敏だけは、今より良い向き（正面 < 側面 < 背面）の範囲を、上の範囲の規則で候補にする。
  - 経路コストが今の方角の 1.5 倍以下の候補があれば、そのうち最も良い向きを選ぶ。同じ向きなら安い方（迷った点3）。
- 予備隊の台本は、指定なしと同じ扱いにする。R3 の性格の規則に従う。

**着く前と着いた後**
- 着く前（範囲・指定なし）：30秒ごとの引き直しのたびに、上の規則で方角を選び直す。
  - 敵へまっすぐ近づいている間は、今の方角は変わらない（発起点が自分と目標を結ぶ線の上にあるため）。方角が動くのは、回り道をしたときと、目標が向きを変えたときだけ。
  - 0.8 倍の揺れ止めは、経路コストで選ぶ場面（側が同点のとき、機敏の候補）に掛ける。今の候補から替えるのは、新しい候補のコストが今の候補の 0.8 倍未満のときだけ。
- 着いた後：P1d のとおり、方角を固定する。
- P1d の `ReconsiderFlankSide` と `AttackSideLocked` はなくし、上の規則に置き換える。

## 5. 命令の下見と経路の表示

**Sim**
- `Simulation.Preview(Order) → OrderPreview` を足す。中身は、目的地（発起点）、経路点の列、攻撃なら方角と結果の向き。
  - 実際の命令の開始と同じ関数で計算するが、状態を変えない。ログも出さず、乱数も使わない。
  - 露出の地図・敵のマスの使い回し（キャッシュ）も、下見では作らずに一時的に計算する。
  - 下見を挟んでも結果が変わらないことを、ログのハッシュで確かめるテストを置く。
- `Simulation.PendingOrderOf(companyId)` を足す。出した命令は、次の刻みの始めに受け付けられるまで待っている。今の作り（刻みの始めにまとめて受け付ける）は変えない。
  - 命令を受け付ける時機を変えると、通し実行の結果が変わる。表示の都合で結果を変えないために、こうした。

**View**
- 下見：前進・後退・陣地構築（目的地あり）・拘束・攻撃の命令を選んで地図にカーソルを重ねている間、目的地と経路を薄く描く。
  - 攻撃では、方角をドラッグしている間も描く。
  - 計算は、カーソルのマスが変わったとき、またはドラッグの方角が 2° 以上変わったときだけ行う。
- 出した直後：受け付け待ちの命令があれば、その下見の経路と目的地を、通常の経路の色で描く。一時停止中も描く。
  - 受け付けられた後は、実際の経路を描く。
  - 露出の地図は 10 秒ごとに作り直すので、下見と実際の経路がわずかに違うことはあり得る。

## View の操作

**攻撃**
- 敵の駒の上でボタンを押し、外へ 20px 以上ドラッグして離すと、地図の方角での指定になる。
  - ドラッグの間に描くもの：
    - 目標の中心から、その方角への線。
    - 250m の発起点。
    - 経路の下見。
    - 結果の向きの文字（正面・側面・背面）。
  - 離さずに Esc を押すと取り消す。
- ドラッグせずにクリックすると、範囲での指定になる。範囲は F・S・B・0（指定なし）で選ぶ（今のキーのまま）。
- 駒の端をクリックして側を選ぶ操作はなくす。
- 右パネルのボタンも、範囲の選択（指定なし・正面・側面・背面）だけにする。

**拘束**
- 遠い／近いを切り替える。右パネルのボタンと、拘束の命令を選んでいる間のキー **D**（Distance）。初期は遠い。
  - D は今どこにも使っていない。
  - 攻撃の「崩れたら…」の C と同じく、命令を選んでいる間だけ効くキーにした。
- 命令の欄に「拘束（遠い 350m）」のように出す。

**印**
- P1c の行動の印と同じ系統で、駒の横に小さく出す。
  - 横歩き：横向きの二重の山形。
  - 後ろ向き：今の後退の印。
  - 旋回中：曲がった矢印。
- 状態の欄にも「横歩き・後ろ向き・旋回中」を出す。

## 迷った点（提案つき）

1. **「抜けている間」の範囲**
   - 仕様の文言は「矩形が重なっている間は押し離しをしない」。
   - 押し離しは中心どうしが 200m 未満で始まり、矩形（奥行 50m）が重なるのは中心どうしが前後に 50m 未満のとき。文言どおりにすると、重なる手前で押し戻されて、抜けられないままになる（R3 の問題が残る）。
   - 提案：押し離しをしないのは、上の「超越中」（経路がその味方の圏を通る、または矩形が重なる）の間とする。×0.5 は文言どおり、矩形が重なる間だけとする。
2. **接敵していないときの後退**
   - 提案：今のまま、背後の弧の目的地なら後ろ向き ×0.6 とする（背を向けて下がるのは壊走だけ、という P1a の規則を守る）。
   - 仕様の「接敵していなければ曲がりながら進む」を後退にも当てはめると、敵が見えないときは振り向いて普通の速さで下がることになる。どちらにするか、ご判断ください。
3. **機敏が他の範囲を選ぶ規則**
   - 提案：今より良い向き（正面 < 側面 < 背面）の範囲だけを候補にし、1.5 倍以下の候補のうち最も良い向きを選ぶ。
   - 今より悪い向きへ替えることはしない。
4. **接敵を始めたときの向き**
   - 仕様の文言どおり、接敵した瞬間の向きを保つ（敵の方へ向き直らない）。
   - 接敵していない間は進む方角へ旋回しているので、ふつうは進む方角を向いたまま接敵する。
   - 横から撃たれたときの向き直りは、P1d の規則（向き直り）に任せる。
5. **「拘束＋迂回」の残りの中隊**
   - 6節の割り当て（B4 が 2分後に同じ側面へ続く、B3 は正面の南で火力支援）でよいか。
