# P2a 設計報告（着手前）：伝令

対象：docs/spec.md「P2a：伝令（確定）」と「時間と命令系統」。返答をいただくまで実装しません。
着手前に、今の `main`（5f4dab8、`proto-p1g.1-fix`）にタグ `proto-p1-map` を打って push しました。

## 1. 命令の状態の持ち方

伝令1人を `Runner`（Sim の中の記録）として持つ。1つの命令に1人。

| 状態 | 意味 | 次へ移る条件 |
| --- | --- | --- |
| 準備（Preparing） | 本部で準備中。判断枠を1つ使う | 発令から 30秒 |
| 往路（Outbound） | 秒速 3m で、中隊の**今の**位置へまっすぐ向かう（毎刻み向き直す＝追いかける） | 中隊の中心に着く（残りの距離が1刻みの移動以下） |
| 受け渡し | 中隊に命令を渡す（下の「開始待ち」へ）。伝令は同じ刻みに帰路へ | — |
| 帰路（Returning） | 秒速 3m で本部へまっすぐ戻る | 本部に着く → **受領**。判断枠が空く |
| 倒れた（Lost） | 往路・帰路で倒れた。命令は届かず、受領も来ない | — |

中隊の側は次の2つを持つ。

- **開始待ち**：届いた命令と、動き出す時刻（届いた時刻＋練度の遅れ。新兵 40秒・通常 25秒・古参 15秒。既存の `order_start_sec`）。その時刻になったら、今の `ApplyOrders` と同じ処理で命令を始める（動揺中の前進・攻撃の拒否、後退の離脱の判定なども、始める時点で判定する）
- **実行中**：今の `CurrentOrder`。開始待ちの間も、古い命令で動き続ける

上書きの規則：

- 開始待ちの間に別の命令が届いたら、開始待ちを新しい命令に置き換える。動き出す時刻は、新しい命令が届いた時刻から数え直す
- 古い命令の伝令が、新しい命令の伝令より後に着いた場合は、その命令を捨てる（迷った点1）

判断枠の強制開放：

- 発令の時点で、往復の予定時間を「30秒＋（本部から中隊までの今の距離÷3m）×2」と決める
- 発令からその 1.5倍が過ぎても受領が来なければ、枠を空け、「受領報告なし」を出す
- その後に伝令が戻っても、枠は増やさず、出来事の欄に「（遅れて）受領」とだけ出す

## 2. Sim の口

- `Simulation.Issue(order)`（今の口。次の刻みの始めに受け付ける）は**そのまま残す**。伝令を使わない場面で使う：
  - 本部のない場面（S1〜S6、単体テスト）
  - 通し実行の開始前の命令（下の 6）
- `Simulation.SendOrder(order)` を足す：本部から伝令を出す。結果は「送った／判断枠がない／本部がない」
  - 本部のない陣営では `Issue` と同じにする
  - View の命令はこの口を使う
- 本部の位置は、シナリオの定義（`MapScenario`、C#）に持たせる：青 (100, 800)、赤 (2700, 1000)。`Build` が `Simulation.SetHeadquarters(side, pos)` で渡す。地図ファイルは変えない
- 表示のための読み取り口：
  - 伝令の一覧（位置、状態、向かう中隊、命令）
  - 中隊ごとの未着の命令と到着予定（準備の残り＋今の距離÷3m）
  - 開始待ちの命令と動き出すまでの秒数
  - 判断枠（使っている数・上限）
- ログ：`runner_sent`、`runner_delivered`、`order_start`、`runner_returned`（受領）、`runner_lost`、`receipt_overdue`（受領報告なし）
- 決定性：伝令の喪失の乱数は、戦闘の乱数とは別の流れ（同じシードの PCG32 の別ストリーム）から引く。伝令の数で戦闘の乱数の並びがずれないようにするため

## 3. 伝令の喪失と射界の判定

- 伝令の陣営から見た敵の射界：P1a の露出の地図（`ExposureFor(伝令の陣営)`）を使う。マスの中心が、400m 以内にいる指揮下の敵のどれかから見えていれば射界。10秒ごとに作り直す、今と同じもの
- 毎刻み、伝令が今いるマスが射界なら、1−0.997^0.5（＝1刻み 0.5秒分）の確率で倒れる。100秒通れば生存率は 0.997^100 ≒ 74%
- 本部の上や、地図の外にはみ出した点は射界に数えない

## 4. ほかの段との関係

- **P1e の命令の下見**：命令を選んでいる間の下見は今のまま。出した命令は、未着・開始待ちの間も、その命令の下見（中隊の今の位置から）を薄く出す（今の「受け付け待ち」の表示を置き換える）
- **P1d の追撃の許可・確保**、**P1d の向き直り**、**P1g の見える位置を探す動き**、**P1e.1 の阻まれた中隊の引き直し**：どれも中隊長が自分で判断するもので、伝令は使わない（今のまま）
- **向き直った向き・確保の命令**：新しい命令が始まった時点で解ける（今は「新しい命令が出るまで」。出る＝始まる、に読み替える）
- **予備隊の台本（赤）**：
  - 引き金の条件を満たした刻みに、赤の本部が R3 へ攻撃の伝令を出す。目標はその時点で決める（今と同じ選び方）
  - 台本の経路の重み（脅威の重み 0）は、命令が始まった時点で付ける
  - 赤の判断枠は数えない。赤の伝令も射界で倒れうる。倒れたら逆襲は起きない（台本は一度きり）
- **壊走中・再集結中の中隊への命令**：伝令は追いかけて渡す。始める時点で指揮下でなければ、今と同じく捨てる。受領は戻る
- **盤上にいない中隊**（降伏・離脱）：伝令は渡さずに本部へ戻る。受領は戻る（「届けられず」と出す）

## 5. 表示（View）

- **本部**：軍隊符号の旗（竿と小さな長方形の旗。陣営の色）と「本部」の文字
- **伝令**：小さな点で、本部と向かう中隊を結ぶ点線の上を動く。行きは黄、帰りは水色
- **未着の印**：
  - 中隊の駒の脇と左パネルに「未着 あと 95秒」（到着予定。追いかける分は今の距離で見積もる）
  - 届いてから動き出すまでは「受領 開始まで 20秒」
- **上部バー**：判断枠「伝令 ●●○」（出ている数だけ塗る）。3人とも出ていれば、命令のボタンを押せなくし、「伝令が出払っている（最初に戻る予定まで あと N 秒）」を出す。キーで命令を選んでも同じ
- **出来事の欄**：「第2中隊 命令受領」「第2中隊 受領報告なし（伝令が倒れた可能性）」。赤の伝令の出来事は出さない
- **自動一時停止**：「受領報告なし」を足す

## 6. 通し実行の作戦の命令

- **時刻 0 の命令は「開始前の命令」**として、伝令を使わずに今の `Issue` で渡す（会戦の前に伝え終えている、と読む）。判断枠も使わない
  - 迷った点2。全て伝令にすると、4個中隊のうち1個は判断枠が空く（約7分後）まで待つことになる
- **時刻 0 より後の命令**（「拘束＋迂回」の B4 の2分後、両翼包囲の B4 の20分後）と**条件つきの命令**（R1 が崩れたら全中隊が村へ）は `SendOrder` で伝令に載せる。判断枠がなければ、空くまで毎刻み出し直す（通し実行の道具の側で待つ）
- 結果が変わる主な理由の見込み：
  - 赤の逆襲が遅れる（ステージ1：R3 まで 250m で約 2分、ステージ2：725m で約 4.5分、それぞれに練度の遅れ）
  - 赤の伝令が射界で倒れうる
  - 青の後からの命令が遅れる
  - 回帰の指標として扱い、作り込みはしない

## 7. パラメータのキー（提案。新しい区分 `runners`）

| キー | 値 | 意味 |
| --- | --- | --- |
| `prep_sec` | 30 | 発令から伝令が出るまで |
| `speed_mps` | 3.0 | 伝令の速さ（行きも帰りも） |
| `loss_per_sec` | 0.003 | 射界を通る間、1秒あたりに倒れる確率 |
| `overdue_mult` | 1.5 | 往復の予定時間のこの倍で、受領が来なければ判断枠を空ける |
| `max_out` | 3 | 判断枠（同時に外に出ている伝令の上限。青だけ数える） |

練度の遅れは既存の `training.*.order_start_sec` を使う。本部の位置は仕様のとおり C# に持たせる。`sim_params.json` には返答の後に仮に足して進めます（同一性のテストは、仕様側の反映まで落ちます）。

## 8. テスト（予定）

- 仕様の検算：
  - 600m の中隊への命令が 230秒で届き、練度の遅れの後に動き出す
  - 約 430秒で受領が戻り、判断枠が空く
  - 射界を 100秒通る伝令の生存率が約 74%（多数回の試行で）
- 届くまでは古い命令が続く。後から出した命令が上書きする（古い命令の伝令が後から着いたら捨てる）
- 判断枠が3で止まる（4つ目は「判断枠がない」）
- 受領が来なければ（伝令が倒れたら）、往復予定の 1.5倍で枠が空く
- 動く中隊を伝令が追いかけて届ける
- 一時停止中（刻みを進めない間）に出した命令も、同じ遅延で届く
- 赤の予備の逆襲が、伝令が R3 に着いて練度の遅れの後に始まる
- S1〜S6 は変わらない（本部がなく、命令もない）。±15% 以内を確かめる

## 迷った点（提案つき）

1. **「後から着いた命令が上書き」と、出した順の食い違い**：同じ中隊に A、B の順に出し、A の伝令が先に倒れずに着けば、順に上書きされて B が残る。普通は A が先に着くので問題ない。A の伝令が何かの理由で B より後に着いた場合（追いかける距離の差など）、字面どおりなら古い A が残る。**提案：出した順で新しい命令を優先し、古い命令が後から着いたら捨てる**
2. **通し実行の時刻 0 の命令**：上の 6 のとおり、開始前の命令として伝令を使わない案を提案する。プレイヤーの会戦も同じく「開始前の命令」の時間（一時停止のまま、伝令なしで初めの命令を出せる）を設けるかは、今回は入れない（仕様にないため）。必要なら決めてほしい
3. **倒れた伝令の点**：P2a では敵が全て見えている（霧は P2b）ので、倒れた伝令の点はそのまま消える。本部は知らないはずのことが画面で分かってしまうが、出来事の欄には出さない。P2b で、本部の知っていることだけを見せる形に揃える想定
4. **「中隊に着いた」の判定**：中隊の中心に着いたとき。検算の 230秒（30＋600÷3）に合わせるため。駒の矩形の端で渡すと、横から近づいたとき最大 100m 分（約 33秒）早くなる
5. **伝令が倒れる場所**：往路・帰路とも、マスの中心が射界なら倒れうる。本部の近くのマスも、敵の射界に入っていれば同じ
6. **赤の伝令の判断枠**：仕様どおり数えない。赤の出来事は欄に出さない（赤の本部の事情は青から分からない）
