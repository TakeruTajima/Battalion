# R1 設計報告：開けた所を動く代償と制圧

依頼文 `docs/handoff/R1_handoff_prompt.md` と、`docs/spec.md` の「R1：開けた所を動く代償と制圧（確定）」に沿った設計。返答があるまで実装には入らない。

## 1. 火力の量の計算の置き場所

- **計算の場所**：損害の同時解決（`Simulation.Resolve`）で射撃ごとの λ を計算している場所で、同時に積む。
  - 射撃ごとの値は `k × 兵数 × f_質 × f_距離 × f_向き × f_状態 × f_その他` で、損害の式から守りの `f_地形` だけを除いたもの（毎分）。
  - `f_地形`（`TerrainDamageMult`）には、地形・塹壕・陣地構築・浅い掩体・規則1 の倍率が入っている。
  - 目標ごとに足して `Company.IncomingFirePerMin` に入れる（その刻みの値。表示と記録にも使う）。
- **λ との違い**：λ は乱数で損害数になる。火力の量は期待値なので、乱数を使わない。
- **制圧の状態を更新する場所**：`Resolve` の直後に `UpdateSuppression(t)` を置く（向き直りの反応の前）。
  - 新しい状態は、次の刻みの移動・射撃から効く。
  - 刻みの初めの状態から同時に解決するという、今の作りと同じ形になる。

## 2. 制圧の状態と、ほかの仕組みとの関係

**状態**：`Company` に次を足す。
- `Suppressed`（制圧下）
- `SuppressOnSec`／`SuppressOffSec`（条件が続いた秒数）
- `IncomingFirePerMin`

**始まりと終わり**：0.5秒の刻みで数える。
- 火力の量がしきい値以上の刻みが 20 続いたら（10秒）、制圧下になる。
- しきい値 ×0.5 未満の刻みが 40 続いたら（20秒）、解ける。
- 途中で条件が途切れたら、数え直す。

**姿勢としきい値**：
- 「動いている」とは、移動を伴う命令（前進・後退・攻撃・拘束）でまだ着いていないか、自律行動の移動の途中であること。この場合のしきい値は 1.5 で、性格の倍率を掛ける（猪突 ×1.5、慎重 ×0.75）。
- それ以外は「止まっている」で、しきい値は 3.5（性格によらない）。
- 伏せて止まっている間も、命令はまだ着いていないので「動いている」のしきい値のまま。解けるのは 0.75 未満が 20秒続いたとき（猪突なら 1.125 未満、慎重なら 0.5625 未満）。
- 規則1 の「動いている」は、その刻みに実際に動いたか（今の `MovedThisTick`）で決める。伏せている間は動いていないので、倍率は掛からない。

**ほかの仕組みとの関係**

| 相手 | 扱い |
| --- | --- |
| 移動 | 制圧下で接触の距離にいなければ、`Move` でその刻みは動かさない。経路・行き先・「着いた」はそのまま残す。向きは、火力の量が一番多い射手の方へ、ふつうの回る速さで向ける |
| 命令・段 | 段は捨てない。解けたら、練度の遅れなしでその刻みから動きを続ける。制圧下で新しい命令が届いたら受け取って段を切り替えるが、動くのは解けてから。始めの遅れ（練度）は今どおり数え、制圧中に過ぎてもよい |
| 段の移り | 「完了したら」は、着くまで移らない（止まっている間は待つ）。時刻の移りは今どおり進む |
| 動揺で停止中（P2b.2） | 別の仕組みで、両方が同時に立ちうる。動揺の停止は命令を保持に変えるので、その間の姿勢は「止まっている」になる。立ち直って段を再開しても、制圧下なら解けるまで動かない |
| 拘束（150m） | 拘束の点へ動く間は「動いている」。着いた後は「止まっている」。拘束の効果（近い敵に足止めされる）は今どおり |
| 自律行動・独断 | 制圧下の間は、移動を伴うもの（物陰へ寄る、独断の追撃・攻撃・回り込み・後退、陣地に入る）を始めない。途中のものも止まり、解けたら続ける。向きの規則は今どおり。浅い掩体を掘るのは移動ではないので、続けてよい |
| 撃つ力 | 制圧下の射手は、`f_状態` に `fire.suppressed_mult`（0.5）を掛ける。接近戦の間も効く |
| 接触の距離 | 自分の矩形と敵の中隊の矩形の隙間が 50m 以内（今の接敵の判定と同じ）の間は、伏せて止まる効き目を出さない。状態の数え方と撃つ力 ×0.5 は今どおり |
| 壊走・再集結・降伏・離脱 | 指揮下でなくなったら、制圧の状態と数え方を消す |
| 赤 | 両方の陣営に同じに効く |

**記録とログ**：ログに `suppressed`（火力の量・しきい値・姿勢）と `suppression_end` を出す。出来事の欄では、同じ中隊で 30秒以内の繰り返しを出さない（表示の側で間引く。ログは全て残す）。

## 3. S7〜S9 の作り（期待の判定）

S1〜S6 と同じ `Scenario` の形で、`Scenarios` に足す。

- 開始時の命令を足せるようにする。伝令は使わず、`Issue` で渡す。
- 各 20 シード。

| 場面 | 配置（守備 R は x=400 で西向き） | 命令 | 終わり | 判定 |

| S7 | 攻め A・B・C を x=0、y=−200／0／200 に東向きで置く（味方どうしの間隔 200m に合わせる） | 3個中隊とも、守備の位置へ前進（突撃。下の迷った点 1） | R が指揮下でなくなる、攻めが全て指揮下でなくなる、または 30分 | R が崩れる割合 ≤ 0.2。かつ、攻めの損害の平均 ≥ 25% か、攻めの1個中隊以上が壊走する割合 ≥ 0.5 |

## 4. 値の掃き出し

**範囲**：3つの値を、それぞれ次の候補で全ての組み合わせを回す（3×3×3 = 27組）。
- `terrain.moving_open_damage_mult`：2・3・4
- 動いている間のしきい値：1.0・1.5・2.0
- 止まっている間のしきい値：2.5・3.5・4.5

27組 × 3場面 × 20シード = 1,620回。

**所要の見込み**：数分。
- 平地の小さな場面（4個中隊・30分まで）なので、1回 0.1〜0.2秒の見込み。
- 初めに1組だけ測って、全体が 15分を超えそうなら、回し方を書いて止まる。

**値の選び方**：期待を全て満たす組のうち、初めの案（2〜4 の真ん中・1.5・3.5）に一番近いものを選ぶ。満たす組がなければ、満たせない期待の数が一番少ない組を報告する。

**掃き出しのやり方**：テストの中で、パラメータの文字列を置き換えて回す（`TestUtil` の置き換え。ファイルは変えない）。

**見込みの懸念（S7）**：今の規則のままだと、S7 は「失敗する」を満たしにくい見込み。
- 3個中隊が動きながら撃つと、守備が受ける火力の量は約 6.0 で、止まっている間のしきい値 3.5 を越える。守備はすぐ制圧下になり、撃つ力が半分になる。
- 守備は一度に1個中隊しか撃てないので、撃たれた1個中隊だけが伏せる。残りの2個中隊は撃たれずに詰められる。

掃き出しの結果で確かめるが、満たせない場合の直し方として、「動きながら撃つ中隊の撃つ力を下げる（たとえば ×0.5）」が考えられる。
- 立って進みながら撃っても当たりにくい、を表す。
- S7 では守備が制圧されにくくなる（3個中隊でも約 3.0）。S8 では止まって撃つ2個中隊で約 4.0 になり、守備が制圧される。「抑えてから詰める」との差がはっきり出る。

これは仕様にない規則なので、入れない。満たせなかったときに、報告で判断を頼む。

## 5. S1〜S6 への影響の見込み

- 規則1 は効かない（止まって撃ち合う場面）。
- 規則2 は、2個中隊以上に撃たれる赤 R に効く。S2 は 2.0×2 = 4.0、S3 は側面 ×1.5 を含めて約 5.0、S4 は約 6.0、S6 は約 8.0 以上で、どれもしきい値 3.5 以上。10秒後に制圧下になり、R の撃つ力が半分になる。
  - その結果、A の損害率がおおよそ半分になり、±15% を外れる見込み（S2 の 0.168 → 約 0.09 など）。
  - R の壊走の時刻と R の損害率は、青の火力が変わらないので、ほぼ変わらない見込み。青は1個中隊にしか撃たれないので（2.0 < 3.5）、制圧されない。
  - H3（側面攻撃は正面攻撃の約半分以下の時間）は、壊走の時刻がほぼ変わらないので保たれる見込み。
- S1・S5 は 1対1 で、火力の量は 2.0〜2.4（< 3.5）。変わらない。
- **したがって、仕様側に v4 を頼む見込み**。Python で同じ規則を作るのに要る点は次のとおり。
  - 火力の量：上の1 の式。守りの `f_地形` だけを除き、射手の動揺 ×0.7・正面の外の目標 ×0.5・制圧下 ×0.5 は含める。
  - しきい値：S1〜S6 は全て「止まっている」で 3.5。
  - 揺れ止め：刻み 0.5秒で、20刻み続いたら始まり、しきい値 ×0.5 未満が 40刻み続いたら解ける。
  - 効き目の順番：その刻みの射撃（刻みの初めの状態）で火力の量を積む → 損害と士気をまとめて適用 → 制圧の状態を更新 → 撃つ力 ×0.5 は次の刻みの射撃から。
- **v4 が届くまでのテスト**：S1〜S6 の照合は、制圧を止めた値（しきい値をとても大きくする）で v3 と比べ続ける。制圧以外が変わっていないことの見張りになる。制圧を入れた値は表に出すだけにする。v4 が届いたら、制圧を入れた値で v4 と比べる形に切り替える。

## 6. パラメータのキー

`Assets/StreamingAssets/sim_params.json` は、`docs/reference/sim_params.initial.json` と同じであることをテスト（`SimParamsIsIdenticalToInitial`）で確かめている。`docs/reference/**` は変更しないので、次のキーを仕様側で `sim_params.initial.json` に足してもらい、それを写す形にしたい。値は掃き出しの後に決める。

```json
"suppression": {
  "threshold_moving_per_min": 1.5,
  "threshold_stationary_per_min": 3.5,
  "onset_sec": 10,
  "release_ratio": 0.5,
  "release_sec": 20,
  "moving_threshold_personality_mult": { "cautious": 0.75, "calm": 1.0, "agile": 1.0, "reckless": 1.5, "scripted": 1.0 }
}
```

- 撃つ力は、今の `fire.suppressed_mult`（0.5）を使う。
- 規則1 は、今の `terrain.moving_open_damage_mult` の値を変える。
- 性格の名前は、今の `sim_params.json` の書き方に合わせる。
- 出来事の欄の 30秒の間引きは、表示の側の定数にする（Sim の値ではないため）。

## 9. 迷った点と、提案する素直な解釈

1. **S7 の「攻撃（正面）」**：今の Sim の攻撃は、守備から 250m の発起点まで進んで止まり、撃ち合う命令で、詰めて踏み込む動きはない。そのまま使うと S7 は 3対1 の火力戦になり、時間をかければ攻めがほぼ必ず勝つ（規則1 も、250m で止まった後は効かない）。仕様の物差し（突撃だけで勝ててしまう）と、シナリオA の「総員突撃」（前進の命令）に合わせ、**守備の位置への前進（突撃）で作ることを提案する**。S8 の B も同じ。
2. **S9 の「撃ち返さずに」**：撃たない命令はないので、前進の命令で動くだけにする（撃てる敵がいれば今の規則どおり撃つ）。塹壕の守備には ×0.3 が効くので、ほとんど効かない。
3. **S8 の「5分後」**：会戦の初めから5分後とする（A・C が 300m に着くのは約 2分後）。
4. **火力の量に含めるもの**：守り（`f_地形`）だけを除き、向き（側面 ×1.5・背面 ×2.0）、射手の状態、追撃・離脱中の倍率は含める。仕様の目安（1個中隊 2.0、2個中隊 4.0）は正面の場合と読む。
5. **伏せている間のしきい値**：始まったときの「動いている」のしきい値のまま、その半分を下回れば解ける（上の2）。止まっている間のしきい値（3.5）に切り替えると、伏せた途端に解けやすくなり、伏せる意味が薄れるため。
6. **後退の命令**：制圧下では後退も動かない（「伏せて止まる」のまま）。後退だけは動けるようにする案もある。プレイの手触りで決めてほしい。
7. **新しい命令**：受け取るが、動くのは解けてから。
8. **向き**：伏せるときは、火力の量が一番多い射手の方へ向く。その後の向きの規則（撃ってきた敵へ向く等）は今どおり。
9. **浅い掩体**：伏せている間も掘り続けてよい（移動ではないため）。
10. **パラメータ**：新しいキーは、仕様側で `sim_params.initial.json` に足してもらい、写す（上の6）。
