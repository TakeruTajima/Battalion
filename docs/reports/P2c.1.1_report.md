# P2c.1.1 報告：接触の距離の敵と「接敵中」

仕様「P2c.1.1：接触の距離の敵と『接敵中』（確定）」を実装した。

| 基準 | 結果 |
| --- | --- |

| .NET でテストが全て通る | 261件全て通過（通し実行の表とログのハッシュを含む） |

## 変わったこと

- **「接敵中」の判定**（`SimulationMovement.cs` の `EnemyInContact`）：400m 以内に視線の通る指揮下の敵がいる、に加えて、接触の距離（`InFireContact`。矩形の隙間 50m 以内）の指揮下の敵を視線を問わずに数える。撃ち合いの規則（`SightForFire`）と揃えた
  - 接敵中は今どおり、向きを変えずに動く（正面の弧へは前進、横は横歩き ×0.5、背は後ろ歩き ×0.6）
- 値は増やしていない（接触の距離は今の `behavior.sight_contact_gap_m` の 50m）

### テスト（`P2c11Tests`、2件）
- 稜線（高さ 30m）を挟んで、矩形の隙間 40m に敵がいる。視線は通らない。北の敵を向いたまま東へ前進すると、接敵中として向きを保ち（90° のまま）、横歩き・後ろ歩きの速さで動く。経路は敵の周りのマスを避けるので、まず南東へ下がる（後ろ歩き）
- 稜線がない（視線が通る）場面でも同じく接敵中（P2c.1 から変わらない）
- 隙間をちょうど 50m にすると、1刻み動いただけで隙間が 50m を越え、接敵中でなくなって進む方へ向きを変える。仕様どおりの振る舞いなので、テストは隙間 40m にした

## ほかに、視線だけで敵の有無を見ていて、接触の敵を数えていない判定（直していない。仕様側で決める）

| 判定 | 場所 | 中身 | 接触の敵を数えないと起きうること |
| --- | --- | --- | --- |
| P1d の向き直りの「正面の弧が空いているか」 | `SimulationBehavior.cs` `FrontArcOccupied` | 性格の表 `turn_front_needs_sight` が true のとき、正面の弧の敵を視線が通るものだけ数える | 稜線の陰で正面の接触の距離に敵がいても「正面が空いている」として、脇から撃ってきた敵の方へ向き直り、接触の敵に脇を見せる |
| P2c.1 の自律の向き（正面の弧の 400m 以内に見える敵がいれば向き直らない） | `SimulationAutonomy.cs` `FrontArcHasVisibleEnemy` | 自分から視線の通る敵だけ | 同じく、正面の接触の敵を捨てて別の敵の方へ向く。ただし接触の敵は撃てる目標になるので、撃てる目標がある間は自律の向きを使わない。実際に起きるのは、接触の敵が撃てない（兵がいない等）ときだけ |
| P2c.1 の自律の向きの向く相手（自分から見える 400m・600m 以内の最も近い敵） | `SimulationAutonomy.cs` `NearestVisibleEnemy` | 自分から視線の通る敵だけ | 上と同じ理由で、実際にはほぼ起きない |
| P1g の見える位置を探すときの候補の点 | `SimulationSight.cs` `EngageableFrom` | 候補の点から目標へ視線が通り、射程内か | 候補の点で接触の距離になる（視線なしで撃てる）点を、撃てない点として飛ばす。より近くまで詰める・横へ回る |
| P2c の物陰の「今の目標が見え続ける所」 | `SimulationAutonomy.cs` `FindCover`（`EngageableFrom`） | 同上 | 物陰の候補が接触の距離で撃ち続けられる点でも「見え続けない」と並べる（順位が下がる。拘束は候補から外れる） |
| 露出の地図（経路の脅威、伝令の倒れる場所） | `SimulationMap.cs` `ExposureFor`・`Visibility.Exposure` | 敵から視線の通るマス | 敵の接触の距離のマスでも、視線が通らなければ「撃たれない」マスとして数える。ただし中隊の経路は敵の周り（約 113m）のマスを通らないので、中隊には効かない。伝令には効きうる（敵の矩形のマスは通らないが、隙間 50m 以内の陰のマスは通りうる） |
| 退路の見積もり | `Simulation.cs` `EstimateEscape`（`VisibleCellsFrom`） | 敵から視線の通るマスでだけ、背面を撃たれると見積もる | 稜線の陰の接触の距離の敵から撃たれる分を見積もらない（包囲の判定と逃げる方位が甘くなる） |

### 大きく変わった作戦と理由

勝率の変化は小さい（どの作戦も ±0.15 以内）。

1. **ステージ1の近い拘束（任せる 0.20→0.30、厳命 0.15 のまま）：R1 が崩れるようになった（R1 壊走 9/20→19/20）**
   - P2c.1 で見た負け方（稜線の陰で接触の距離にいる拘束役 B2 が、見える位置を探して横へ動くときに進む方へ向き、R1 に脇と背を撃たれる）が、B2 が向きを保って動くようになって減ったと読む。R1 が崩れる回数は、向きの規則を止めた版と同じくらいに戻った
   - 勝率はそこまで戻らない。B1（側面の攻撃）が 20/20 回壊走し（中央値 29.3分）、R1 の壊走（中央値 58.5分）より先に崩れているため、R1 を崩した後に村まで取れない回が多いと読む（試行ごとの経過は追っていない）
2. **ステージ1の「拘束＋猪突の攻撃（確保）」（任せる 0.30→0.25、厳命 0.30→0.40）と段階つき（任せる 0.25→0.35）**：20回での ±0.10 の揺れ。接敵中の判定が変わると、その後の動きの速さ（横歩き・後ろ歩き）と向きが変わり、試行ごとの経過がずれる。理由を一つに絞れるほどの差ではないと読む
3. ほかの作戦は、勝率が同じか ±0.05

## 迷った点と、自分で決めた点

1. **接触の距離の判定に使う矩形**：今の位置と向きの矩形（`InFireContact` と同じ）。動く前の位置で判定する（今どおり、全中隊が動く前にまとめて判定）
2. **400m の条件**：接触の距離の敵は必ず 400m 以内にいる（隙間 50m）ので、400m 以内の敵の中で、視線が通るか接触の距離か、を見る形にした
3. **テストの隙間**：ちょうど 50m では、1刻み下がっただけで接触の距離を出る。仕様どおりの振る舞いなので、テストは 40m で確かめた
4. **ほかの判定（上の表）**：直していない。とくに P1d の向き直りの「正面の弧が空いているか」は、同じ食い違いで脇を見せうるので、揃えるかは仕様側で決めてほしい
