## 2. 実装したもの

**Sim（会戦の結果を変えない作り）**
- `SimulationIntel.cs`：敵の報告（`EnemyReport`）、報告の駒（`IntelPiece`）、駒の見え方（`PieceLook`）、規模の見積もり（`EnemySize`）、報告の様子（`ReportedState`）。
- 報告を送る時（`WatchEnemies`。P2c.2 の「敵発見」を広げた）：
  - 発見：気付いている指揮下の敵を初めて見た時（600m の限りを外した。会戦の始めにもう見えている敵も報告する）。
  - 続報：その敵と接敵している（400m 以内に視線が通る）間、2分ごと。
  - 変化：見ている敵が、動き出した・止まった・200m 以上動いた・壊走した・降伏した時。
  - 送りすぎを防ぐ決まり（60秒のまとめ、同時に2人まで）、判断枠を使わないのは今のまま。同じ敵の報告がまだ伝令に渡っていなければ、新しい方に置き換える（初めの発見は「発見」のまま中身だけ新しくする）。
- 報告の中身（`MakeReport`）：
  - 位置：見た時の実際の位置に、見た中隊の練度の誤差（`training.*.report_error_m`：新兵 150・通常 100・古参 60m。前からある値）の円の中で一様に散らした点。
  - 規模：多い（7割以上）／半ば（4〜7割）／少ない（4割未満）。新兵は 20% で1段階間違える。
  - 動き：止まっている／動いている（8方位）。様子：壊走中・降伏は正確に。時刻：見た時刻。
  - 誤差と間違いの乱数は、戦闘・本部の伝令・中隊の伝令とも別の系列（`FogStream`）から引く。
- 本部の推定（`ReceiveReport`）：届いた報告を、位置が 300m 以内で見た時刻の差が 10分以内の駒（近い方）に紐付ける。なければ新しい駒。古い報告が後から届いたときは、駒の位置と様子を戻さない。
- 駒の見え方（`LookOf`）：見た時刻から 5分で薄く、10分で「?」、30分で地図から消える（戦闘詳報には残る）。
- 会戦の始めの敵情：地図ファイルの `initial_intel`（位置・規模・向き。時刻 0 の報告）。地図の4つ（と `Assets/StreamingAssets/maps/` の写し）に足した：
  - シナリオA ステージ1：R1（頂上の塹壕）・R2（村）
  - シナリオA ステージ2：R1・R2（斜面の塹壕）
  - 教程1：R1・R2、教程2：R1
  - いずれも配置の位置、規模は多い、向きは西（180°）。R3（予備）は書いていない。
- 報告の駒への命令（`Order.AttackPiece`・`AttackPieceFrom`・`PinPiece`）：
  - 命令を受けた中隊は、気付いている指揮下の敵のうち、駒の位置に最も近い敵（駒の位置から 300m 以内）を目標にする。決まれば今の攻撃・拘束と同じ（攻める方角の選び方 P1e の4 もそのまま）。
  - 決まらなければ、駒の位置へ前進し（元の命令を `Company.PieceOrder` に残す）、毎刻み探す。見えたら、その敵への攻撃・拘束を始める。
  - 着いても見えなければ、その場で保持し「敵を見ず」を具申する（要請：命令を請う。`DispatchKind.NoEnemySeen`）。
- パラメータ `fog` の節（`sim_params.json` と `docs/reference/sim_params.initial.json` に同じ値）：`enabled` true（表示の既定。false で霧なし）、`update_sec` 120、`change_move_m` 200、`size_many_ratio` 0.7、`size_half_ratio` 0.4、`green_size_error_rate` 0.2、`link_radius_m` 300、`link_window_sec` 600、`fade_sec` 300、`unknown_sec` 600、`forget_sec` 1800、`piece_target_radius_m` 300。前の版と比べるテストで報告を止める `Fog.Reports`（JSON にはない）。

**表示**
- 霧の中（`fog.enabled`、会戦の途中）は、地図の赤は報告の駒だけ。駒は赤の破線の形で、誤差の薄い円、動いていれば向きの線。文字は「敵 多い 3分前」、10分で「? 敵 12分前」、壊走中・降伏の印。5分で薄く、30分で地図から消す。
- 実際の赤の駒・文字・赤の伝令・赤が関わる射撃の線は出さない。
- 攻撃・拘束の目標は、報告の駒を選ぶ（駒の誤差の円の中、最低 100m）。攻撃の方角のドラッグも駒の中心から。下見も同じ。
- F12 で「霧なし」（検証用。全ての敵を正確に出す）。会戦が終わったら（戦闘詳報）、実際の赤の駒と報告の駒（地図から消えた駒も薄く）を重ねて出す。
- 具申の文：「B2 敵発見（多い、止まっている）」「B2 敵の続報（半ば、東へ動いている）」「B2 敵の変化（壊走中）」「B2 敵を見ず（命令を請う）」。霧の中では、ほかの具申でも赤の中隊の名前を「敵」にする。

## 3. 霧の入り切りで結果が変わらないことの確かめ

- **霧（`fog.enabled`）は表示だけ**：Sim は `fog.enabled` を読まない。地図に出すものが変わるだけで、会戦は変わらない。
- **報告の規則（P2d で足した報告を送る判定・本部の推定）**：
  - 報告の誤差・規模の間違いは、戦闘と別の乱数の系列から引く。報告の駒は、中隊長の判断にも赤の判断にも使わない（使うのはプレイヤーの駒への命令だけで、通し実行の作戦は今までどおり中隊の ID で命令を出す）。
  - `P2dBattleUnchangedTests.ReportsDoNotChangeTheBattle`：報告の規則あり・なし（`WithoutP2d`）で、シナリオA の全ての作戦 × シード1・2（36会戦）の戦闘のログ（中隊の伝令の行を除く）が1文字も違わない。
  - 通し実行：報告の規則ありで回したシナリオA（`ScenarioAReportTests` 5件、所要 29分29秒。報告の判定の分だけ F1 の 25分34秒より長い）と、教程1・2 の表は、F1 の表（報告の規則なしで回したもの）と、全ての行が同じ（シナリオA は表の 132行、教程は全ての行）。

## 4. 迷った点と、自分で決めた点

1. **報告の駒への命令の目標の決め方**：命令を受けた時と、駒の位置へ向かう間の毎刻みに探す。目標が決まった後は、今の攻撃・拘束と同じ（その目標を追う）。駒の位置は命令を出した時の位置で、後で駒が動いても命令は変わらない。
2. **駒へ向かう間は前進の命令**：段階つきの命令書の段としては、元の攻撃・拘束のまま（「完了したら」は、目標が決まって崩れた時）。駒の位置に着いただけでは段は完了しない。
3. **会戦の始めに見えている敵も報告する**：P2c.2 では「会戦の初めに 600m 以内で気付いている敵は既知として報告しない」だったが、P2d では初めの敵情と照らすために報告する（紐付けで同じ駒になる）。
4. **報告の「動いている」**：壊走中か、移動の命令の途中（伏せて止まっている間を除く）。動く向きは、経路の次の点への向き（なければ中隊の向き）を 8方位に丸めた。
5. **中隊の詳しい表示に出す知っていること**：「撃たれている」「撃っている目標」は、仕様が許す試作の形として即座に出す（〇分前は添えていない）。中隊長の目に見えていることとして、赤の中隊の名前もそのまま出る。
6. **出来事の欄**：Sim のログから拾う出来事（例：「R1 壊走」「B2 展開（R1 を発見）」）は、霧の中でも今のまま赤の名前が出る。本部が知らない赤の動きが出来事の欄から分かってしまうので、霧の中での出来事の欄の出し方は、仕様側で決めてほしい（下の 5）。
7. **赤が関わる射撃の線**：霧の中では、青が撃っている線も出さない（線の先が赤の実際の位置を明かすため）。

## 5. 仕様側で見てほしいこと

1. **出来事の欄と霧**：上の 4 の 6。赤の中隊の出来事を霧の中で隠すか、本部に届いた報告から作るか。
2. **射撃の線と霧**：上の 4 の 7。青の射撃の手応え（線）を、報告の駒へ向けて出すなどの形にするか。
3. **会戦の始めの縮合（F1 の報告の 9 の追記）**：初めの敵情が本部にあっても、中隊長の判断（気付いている敵）は視線で決まるので、シナリオA の青は始めに縦隊になる。
