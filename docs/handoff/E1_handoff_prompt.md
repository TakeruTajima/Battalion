# 実装依頼：大隊指揮RTS プロトタイプ E1（赤の守り方の最小版）

## Git タグ

完了時に `proto-e1-defense` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-r2.1-fix` まで完了）。

R2.1 の通し実行で、両ステージとも「村への前進」（全中隊を村へ向かわせるだけ）が勝率 1.00 のまま残った。原因は規則ではなく赤の守り方にある。迂回されても塹壕から動かない、予備は一度逆襲したら終わり、村を取られても取り返しに来ない。P4（敵 AI の本番）より前に、史実の守りの型のうち、今の命令の組み合わせで作れるものだけを入れる。あわせて、逆襲が意味を持つために「奪った直後の弱さ」（C12）のうち乱れを足す。

- 仕様書：`docs/spec.md` の「E1：赤の守り方（最小版）（確定）」が正
- 背景：`docs/design/tactics.md` の「3.5 守る側から見る」（G4〜G7）と C12

## タスク

1. 守りの計画：地図ファイルに `defense_plan` を足し、`reserve_script` を置き換える（配置は変えない。座標は仕様の表）。読み込みと検証（矩形の重なり、座標が地図の中）を足す
2. 規則1：前線の後退（中隊の判断、伝令なし。迂回された かつ 拘束されていない で、後退先へ1回だけ下がる）
3. 規則2：即座の逆襲（予備の判断、伝令なし。繰り返し、余力がなくなるか円が空けば戻る位置へ戻る）。今の赤の予備の台本（伝令あり、一度だけ）は `defense.enabled` = false のときだけ使う
4. 規則3：奪回（赤の本部が 60秒ごとに判断し、伝令で「集結点へ、揃ったら攻撃」の命令書を送る）。比べ用の小出しの版（`retake_mode` = `immediate`）
5. C12：占領の乱れ（両軍）。陣地の持ち主、乱れの撃つ力の倍率、乱れの間は浅い掩体・陣地構築を始めない。`occupation.enabled` で入り切り
6. 赤の判断は「赤の中隊のどれかから視線が通る青」だけを使う
7. 検証の場面 S14〜S19 と、期待を判定するテスト（S17 は数字を報告するだけ）
8. 通し実行（`ScenarioAReportTests`）：主な表を E1 で回す。比べの表（主な4作戦 × 受け身の赤／占領の乱れなし／小出しの奪回）と、出来事の回数を足す。全体で今と同じくらい（約2時間）に収まるよう回数を調整してよい（調整したら報告）
9. 表示：出来事の欄に赤の後退・逆襲・奪回、詳しい表示の倍率に占領の乱れ

パラメータ：`defense`・`occupation` を `sim_params.json` に足す。仕様側で `sim_params.initial.json` に反映するまで、同一性のテストは落ちてよい

## テスト

- 単体テスト：
  - 迂回の判定（線より 50m 後ろ・600m 以内、側面・背面から撃たれた）と拘束の判定（正面の弧 400m）。見えていない青では判定しない
  - 下がるのは1回だけ。着いたら役目が守備になる
  - 予備：伝令なしで動く。目標は守る地点に最も近い青。余力がなくなったら逆襲しない
  - 奪回：条件（村に青、250m 以内に赤なし）、揃うまで待つ（2個 または 600秒）、揃ったら同時に攻撃
  - 占領の乱れ：敵の持ち主の陣地に入ると掛かり、持ち主なしでは掛からない。持ち主が変わる。乱れの間は掘り始めない。`enabled` false で掛からない
  - `defense.enabled` false で今の赤と同じ振る舞い（今のシナリオA のログと一致すること）
- S14〜S16・S18/S19 の期待を満たす。S18/S19 を満たさなければ、仕様のとおり占領の乱れの値を掃き出して選ぶ。どれも満たさなければ、値を変えずに結果と理由を報告して止まる
- S1〜S13 が変わらないこと（変わる場合は理由）
- **速いテストは .NET と Unity（バッチモード）の両方を Claude Code が回す**
- **今回はシナリオA の通し実行（`ScenarioAReportTests`、約2時間）も Claude Code が回す**。結果の表を報告に載せ、R2.1 の値（リポジトリのルートの `r3_result.txt`、未追跡）と並べる。結果のファイルは commit しない
