# 実装依頼：大隊指揮RTS プロトタイプ P1e（行動と命令の改善）

## Git タグ

完了時に `proto-p1e-orders` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p1d-behavior` まで完了）。

P1d を人が遊び、次の点が見つかった。

- 予備の R3 が味方の後ろに挟まり、逆襲に出られない（P1d の報告の判断点2）
- 横へ動く中隊が、わざわざ敵に側面や背面を向けて大損害を受ける。曲がり角ごとに止まって向きを変える
- 塹壕の正面 125m に詰めた拘束の中隊が、迂回が着く前に崩れる
- 敵の後ろから方向指定なしで攻撃すると、正面へ回り込む。すでに側面の範囲にいるのに、真横の位置まで回り込む
- 一時停止中に出した命令の経路が表示されない

考え方の柱は2つ：「側面を突く」は命令ではなく結果であり、大隊長は「どの方角から攻めるか」を命じる。中隊長は、場面にそぐわない動き（敵の前で横腹をさらす等）をしない。

- 仕様書：`docs/spec.md` の「P1e：行動と命令の改善（確定）」が正。数値もそこにある
- 将来の候補「隊形（縦隊と横隊）」は P2 以降。今回は作らない

## タスク

仕様の「P1e：行動と命令の改善（確定）」の1〜6を実装する。

1. 隊列の超越（止まっている味方の周りをコストに、抜ける間は押し離しなし・×0.5）
2. 動くときの向き（接敵中は向きを変えずに前進・横歩き・後ろ向き。接敵していなければ曲がりながら進む）
3. 拘束の距離（遠い 350m／近い 125m。初期は遠い）
4. 攻撃の方向を「攻める方角」で指定（ドラッグでの方角、F・S・B の範囲、指定なしは今の方角から、台本は指定なし扱い）
5. 命令の下見と、命令を出した直後の経路の表示（一時停止中も）
6. 通し実行に「拘束＋迂回」（遠い拘束版と近い拘束版）を足す

表示（View）：
- 攻撃：敵の駒をクリックしてそのまま外へドラッグすると方角の指定。ドラッグの間、方角の線・発起点・経路の下見を出す。F・S・B は今どおり範囲の指定として残す。駒の端をクリックして側を選ぶ操作は廃止する
- 拘束：「遠い／近い」の切り替え（右パネルのボタンとキー。キーは設計で決める）
- 横歩き・後ろ向き・旋回中が分かる印（P1c の行動の印と同じ系統）

パラメータ：新しい数値は `sim_params.json` に置く。キーは設計報告で提案する（仕様側で `sim_params.initial.json` に反映する）

## テスト

- 1〜5の単体テスト（例：味方の間 250m を抜けて逆襲に出られる、抜ける間に押し離しがない、接敵中に横の目的地へは向きを変えず ×0.5 で動く、接敵していなければ曲がり角で止まらない、遠い拘束は 350m で止まる、南南西から側面の範囲を指定すると今の方角から攻める、敵の後ろから指定なしなら背面になる、ドラッグの方角が守られる、一時停止中に命令を出すと経路がすぐ引かれる）
- S1〜S6 は v3 の正解値の ±15% 以内のまま。変わったら理由を報告する
- 5作戦＋「拘束＋迂回」の通し実行の表を、P1d と並べて報告する。大きく変わった作戦は理由を調べる。「拘束＋迂回」が報われていなければ、どこで崩れているか（拘束役が先に崩れる、迂回が遅い、向き直られる等）を調べて報告する

## 完了基準

- Unity 6.3 LTS（6000.3.11f1）と .NET でテストが全て通る
- S1〜S6 の扱いと、通し実行の表と理由が報告にある
- `Sim` が UnityEngine を参照しない
- 報告に、人が触って確かめる項目の一覧と、変わった操作の早見表を含める

## スコープ

- 含める：上のタスクのみ
- 含めない：隊形（縦隊・横隊）、伝令・霧と報告（P2）、砲兵（P3）、敵AI（P4）、戦闘詳報（P5）、P1d の保留の3点
- 地図データとリファレンス実装は変更しない

## 方針

- **着手前に設計を短くまとめて報告し、返答があるまで実装に入らないこと。** 特に、接敵の判定と向きの規則の組み合わせ（攻撃・拘束・後退の命令との関係）、隊列の超越と P1d の押し離し・敵を避ける規則の関係、方角の指定の操作、パラメータのキー、S1〜S6 と通し実行への影響の見込みを書く
- 仕様の解釈で迷ったら一覧に残し、もっとも素直な解釈を提案に含める
- Unity は 6.3 LTS（6000.3.11f1）で開く
- 完了したら止まって報告する。P2 には進まない
