# 実装依頼：大隊指揮RTS プロトタイプ P1c（手応えの見える化）

## Git タグ

完了時に `proto-p1c-feedback` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p1b-view` まで完了）。

P1b を人が遊んだ結果、次の声が出た。

1. 攻撃している／されている／止まっている／陣地を掘っている、が駒を見ても分からない
2. 損害や士気の低下が見えないので、正面でも側面でも「効いている」実感がない。そのため H1（包囲が気持ちよく決まる）と H3（正面は高くつき、側面は速い）は「分からなかった」
3. 全体にもっさりしている。×10 くらいまで速くしたい
4. 村を確保できているかが分からない。勝ったと思ったら負けていた

**Sim の規則は正しく動いている前提で、足りないのは「見せ方」。** P1c は表示側だけで、戦場で起きていることを読めるようにする。仕様の方針「教えるのではなく気付かせる」の土台になる。側面を突いた・突かれた瞬間が、説明なしに目に入ることが目標。

見た目は軍隊符号と図形のまま。絵は作らない。すべて図形・線・文字で描く。

## タスク

### 1. 射撃の見える化

- **射撃線**：撃っている中隊から目標へ線を引く（その刻みに撃った組だけ）
  - 色は、撃たれる側から見た向き：正面＝白、側面＝橙、背面＝赤
  - 太さは損害の期待値（毎分）に比例させる（細い〜太いの幅は見やすさで決めてよい）
  - 線の上を、目標へ向かって流れる破線（曳光弾のような動き）。流れる速さは**現実の時間**で一定にする（倍速を上げても読める速さのまま）
- **発砲の明滅**：撃っている中隊の正面の辺に沿って、小さな明るい点をちらつかせる。数は兵力に比例

### 2. 損害と士気の見える化

- **損害の数字**：中隊ごとに、現実の約1.5秒ぶんの損害をまとめて「−4」のように駒の上に浮かべて消す。主な向きが側面・背面なら色を変え、「側面」「背面」の文字を添える
- **被弾の明滅**：撃たれている駒の枠を光らせる。側面・背面からは強く
- **駒のバー**：駒のすぐ下に兵力と士気の細いバー。士気のバーは、減った分を薄い色でしばらく残してから縮める（直前に大きく削られたことが見て分かるように）
- **大きな出来事の表示**：駒の上に大きめの文字を出して消す。対象は、初めて側面／背面を撃たれた（「側面を突かれた」「背面を突かれた」）、包囲された（駒を囲む赤い輪を、包囲の間は脈打たせる）、壊走、降伏（白旗の図形）、再集結の開始と復帰、予備隊の逆襲

### 3. 行動の見える化

駒の脇に、今していることを図形の印で出す（文字の状態表示と別に）。

| 行動 | 印の例 |
| --- | --- |
| 移動中 | 進む向きの山形（後退中は逆向き） |
| 射撃中 | 1の発砲の明滅で足りるなら印は不要 |
| 保持（止まっている） | 短い横棒 |
| 拘束（命令） | 目標へ向けた短い杭の印 |
| 拘束されている（150m以内から撃たれている） | 駒の周りに細い点線の輪 |
| 陣地構築 | 正面の辺に沿って、進捗に比例して伸びる斜線の帯 |
| 籠城（塹壕・村の中） | 枠を二重線に |

印の形は見やすさで決めてよい。同じ情報を色だけで示さず、形でも分かるようにする。

### 4. 勝利条件の見える化

- **村の目標の印**：村の中心に旗の図形。状態を4つで示す：青が確保（青がいて250m以内に赤なし）／赤が確保／争奪中（両方いる）／空き
- 村の中心から250mの円を薄く描く（判定の範囲が見えるように）
- **上部バーに勝利条件**：「村に青の中隊：○／×」「250m以内の赤：○／×」と、90分までの残り時間。今この瞬間に終わったら勝ちか負けかが常に分かること
- 終了画面の理由は今のまま（P1b で実装済み）

### 5. 時間

- 倍速を ×1／×2／×4／×8／×16 にする。キーの割り当ては今のデバッグ表示（F5〜F7）とぶつからないように決める
- ×16 で、1フレームの刻みの上限（16）に当たって時間が遅れないか確かめる。当たるなら上限を見直す（重さは5作戦の通し実行の速さから見て問題ないはず）
- **自動一時停止**（切り替えられる。初期は有効）：次の出来事で自動的に一時停止し、何が起きたかを上部バーに出す
  - 味方が初めて側面／背面を撃たれた
  - 誰かが包囲された
  - 味方が壊走・降伏した
  - 予備隊が逆襲に出た
  - 村の目標の状態が変わった

### 6. 陣地構築の命令に目的地を持たせる

プレイヤーの声：「この位置に移動して陣地を構築せよ」と命令したい。今は、その場で掘り始めるだけ。

- 陣地構築の命令に、任意の目的地と到着後の向きを持たせる。目的地があれば前進と同じ経路で移動し、着いて向きを変え終えたら掘り始める。目的地がなければ今と同じ（その場で掘る）
- 入力：Y → 地図をクリックで目的地（ドラッグで向き）。今の「すぐ出る」は、Y を押したあと選んだ中隊の駒をクリックするか、もう一度 Y を押す、などで残す（決め方は任せる）
- 選んだ中隊の目的地に、陣地構築の予定であることが分かる印を出す（3の陣地構築の印と同じ系統の形）
- 移動中に動揺した場合は、今の規則どおり保持になる（掘り始めない）
- 単体テスト：移動してから掘り始める／着くまでは進捗が増えない／目的地なしは今と同じ

### 7. 小さな直し

- `docs/reference/sim_params.initial.json` の `_note_moving_open` の注記に塹壕を足す（「平地・砲撃痕・橋・浅瀬・塹壕」）。`Assets/StreamingAssets/sim_params.json` も同じにする

## Sim への変更

- 6の陣地構築の目的地（命令の種類が増えるだけで、既存の命令の挙動は変えない）と、**表示のための読み取り専用の口**を足してよい。たとえば、その刻みの射撃の記録（撃った中隊、目標、向き、損害の期待値、実際の損害、士気の変化）
- 会戦の結果を変えてはいけない。見た目のための乱数（発砲の明滅など）は **Sim の乱数を使わず**、表示側で別に持つ
- 確認：P1b と同じ17通りの全イベントログの SHA256 が一致すること

## 完了基準

- Unity 6.3 LTS でコンパイルが通り、EditMode テストが全て通る（.NET でも通る）
- 17通りのログが P1b と完全に一致する
- `Sim` が UnityEngine を参照しない
- バッチモードの画像で、射撃線（正面・側面・背面の色）、損害の数字、行動の印、村の目標の印が描けていることを自分で確かめ、その画像を `docs/reports/P1c/` に置く
- 報告に、人が触って確かめる項目の一覧と、変わった操作の早見表を含める

## スコープ

- 含める：上のタスクのみ
- 含めない：伝令・霧と報告（P2）、砲兵（P3）、敵AI（P4）、戦闘詳報（P5）、効果音、立ち絵
- Sim の規則と数値は変えない（6の命令の追加を除く）

## 方針

- 表示が中心で、Sim の追加も小さいので、**着手前の設計報告は不要**。そのまま進めてよい。迷った点と、自分で決めた見た目の選択は報告に一覧で残す
- 情報を増やすと画面がうるさくなる。**読みやすさを優先して、出しすぎない**。たとえば射撃線は、選んだ中隊にかかわるものを強く、それ以外を弱く描くなど、判断に必要なものが目に入る工夫をしてよい
- 完了したら止まって報告する。P2 には進まない
