# 実装依頼：大隊指揮RTS プロトタイプ P3（砲兵）

## Git タグ

完了時に `proto-p3-artillery` を打ち、push する（下の条件を満たしたとき）。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p2d.1` まで完了。仕様側の記録の変更が作業ツリーにあれば、最初の commit に含める）。

Takeru が P2d.1 を遊び、霧は手応えがないので初めから切ることにした（仕組みは残して設定で入れられる）。次は砲兵を急ぐ。砲兵は、弾力防御が得になる理由、縦隊の脆さ、砲撃と前進の連動（T17）の土台で、この後の教程に繋げる。

- 仕様書：`docs/spec.md` の「霧はペンディング（2026-11-01）」と「P3：砲兵（確定）」が正。上の「砲兵」の節の数字（160発、毎分8発、電話 30秒、準備 90秒／計画射撃点 30秒、誤差 100m→30m、半径 100m、平地 6.0%・−15）は P3 の節で具体にした

## タスク

0. 霧を既定で切る（霧なしを既定に。設定で入れられる）。射撃の手応えの破線と楔は、霧なしでも出す
1. 地図ファイルの `artillery`（側ごとの野砲中隊と弾数）。シナリオA の両ステージに青・赤とも 160発
2. 青の要請（地点・長さ・始める時刻、要請できる地点の決まり、電話と準備の時間、誤差と観測の修正、取りやめと伸ばし、弾の減り）と、会戦前の計画射撃点の登録（3箇所）
3. 効果（半径 100m、損害と士気、地形・陣地構築・浅い掩体・縦隊の倍率、陣地の向きと R1 の ×3.0 は掛けない、制圧、砲撃痕、誤射）
4. 赤の砲兵（守りの計画の `artillery_points`、赤の本部の判断、誤射を避ける）。シナリオA の地図の守りの計画に計画射撃点を足す
5. 表示（要請の操作、円と残り秒、残りの弾、計画射撃点の登録、倍率、出来事）
6. 場面 S24〜S29 と期待のテスト。期待を外れたら仕様の掃き出し
7. 通し実行：シナリオA に青の砲兵を使う3作戦を足し、比べに赤の砲兵なしの版を並べる。教程1・2 は変わらないこと

パラメータ：`artillery` の節（loss_pct_per_min 6.0、morale_extra_per_min 6、radius_m 100、rounds_per_min 8、phone_sec 30、prep_sec 90、prep_planned_sec 30、error_initial_m 100、error_observed_m 30、observe_after_sec 60、crater_after_sec 180、red_eval_sec 60、red_safety_m 250 など）を `sim_params.json` と `docs/reference/sim_params.initial.json` の両方に足してよい

## テスト

- 単体テスト：要請できる地点の決まり、電話と準備の時間、時刻を指定した要請、誤差と観測の修正、弾の減りと足りない時、取りやめと伸ばし、半径の中の判定、地形・縦隊の倍率、陣地の向きと ×3.0 が掛からないこと、制圧と解ける 60秒、砲撃痕、誤射、赤の要請の順と誤射を避ける決まり
- 速いテストは .NET と Unity（バッチモード）の両方を回す。ログの一致を見るテスト（規則を止めた値で前の版と一致）が通ること。砲兵のない地図・場面の結果が変わらないこと
- 通し実行は Claude Code が回す

## 完了基準と push の条件

- 速いテストが全て通り、S24〜S29 の期待（掃き出しで選んだ場合はその値）、S1〜S23 と教程1・2 が変わらない
- シナリオA で、砲兵を使う作戦の良い方が両ステージで 0.6 以上
- 満たせば `docs/reports/P3_report.md` を書いて commit・タグ・push。満たさなければ止めて報告
- 0.15 以上動いた作戦は、会戦の経過を1件追って原因を書く（それだけでは止めない）

## スコープ

- 含める：上のタスクのみ
- 含めない：対砲兵、破片の散らばり、砲兵の移動、霧の作り直し、R5、新しい教程
- リファレンス実装は変更しない

## 方針

- 着手前の設計報告は不要。迷った点と自分で決めた点は報告に一覧で残す（特に：誤差の散らし方、観測の修正の判定、時刻を指定した要請の操作、赤の要請の目標の選び方、砲撃痕のマス）
- 返事と報告は日本語で書く
