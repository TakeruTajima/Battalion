# 実装依頼：大隊指揮RTS プロトタイプ R6（突撃の最後の一歩：突入と白兵戦、射撃の延伸）

## Git タグ

完了時に `proto-r6-melee` を打ち、push する（下の条件を満たしたとき）。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-t3-barrage` まで完了。仕様側の記録の変更が作業ツリーにあれば、最初の commit に含める）。

教程2・3 で、塹壕の縁に着いた突撃が 1対1 で 8〜20分撃ち合ってから決着していた。史実では縁の戦いは数分で決まる（手榴弾・銃剣・シャベルの白兵戦、肉薄された守り手のパニック）。ただし、伏せていない守り手に、撃たれながら辿り着いた疲れた突撃は跳ね返される。あわせて、ペンディングだった射撃の延伸（R5）を入れる。

- 仕様書：`docs/spec.md` の「R6：突撃の最後の一歩（突入と白兵戦、射撃の延伸）（確定）」が正

## タスク

1. 射撃の延伸：目標の矩形の 50m 以内に指揮下の味方の矩形が入ったら、その目標を撃たない（撃つ中隊自身が接近戦の距離にいる時は除く）
2. 突入の比べ（30秒ごと、押す力と守る力、跳ね返し）
3. 白兵戦（損害・士気・突入の衝撃・比べ直し・白兵戦の中の壊走の降伏）
4. 表示（印、比べの値、出来事）
5. 場面：S7 を 45分でも見る、S8 の「接近戦に入ってから崩れるまで」、S28 (a)(b)、新しい S30、S18・S19。期待を外れたら仕様の掃き出し
6. 通し実行：教程1・2・3 とシナリオA を回し、P3・T3 の値と並べる

パラメータ：`melee` の節（check_sec 30、defense_mult：trench 2.0・scrape 1.3・village 2.0・forest 1.3・plain 1.0、repulse_morale 10、loss_pct_defender 8、loss_pct_attacker 4、morale_defender 20、morale_attacker 5、entry_shock 15、surrender_prob 0.3、loss_ratio_cap 3、village_loss_mult 0.7）と `fire.lift_clearance_m` 50 を `sim_params.json` と `docs/reference/sim_params.initial.json` の両方に足してよい

## テスト

- 単体テスト：射撃の延伸（50m の内・外、自分が接近戦の距離にいる時）、押す力と守る力の倍率、突入と跳ね返し、白兵戦の損害と士気、比べ直しで押し返される、白兵戦の中の降伏、押す力に数える中隊（攻撃・前進の命令だけ）、赤の逆襲でも同じ
- 速いテストは .NET と Unity（バッチモード）の両方を回す。ログの一致を見るテスト（R6 を止めた値で前の版と一致）が通ること
- 通し実行は Claude Code が回す

## 完了基準と push の条件

- 速いテストが全て通り、場面の期待（掃き出しで選んだ場合はその値）を満たす
- 満たせば `docs/reports/R6_report.md` を書いて commit・タグ・push。教程・シナリオA が線を外れても、報告に原因を書いた上で区切ってよい（止める条件は場面だけ）
- 場面の期待を満たさなければ止めて報告

## スコープ

- 含める：上のタスクのみ
- 含めない：霧、新しい教程、弾薬（小銃）
- リファレンス実装は変更しない

## 方針

- 着手前の設計報告は不要。迷った点と自分で決めた点は報告に一覧で残す（特に：押す力に数える中隊の判定、白兵戦と接近戦の射撃の関係、複数の守り手が並ぶ時の比べ方、赤の逆襲の扱い）
- 勝ち方が変わった作戦（教程・シナリオA）は、会戦の経過を少なくとも1件追って書く
- 返事と報告は日本語で書く
