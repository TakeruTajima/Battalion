# 実装依頼：大隊指揮RTS プロトタイプ T2（教程2：抑えてから詰める）

## Git タグ

完了時に `proto-t2-suppress` を打ち、push する（下の条件を満たしたとき）。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-t1-flank` まで完了）。教程の2つ目。回り込む道のない地峡の塹壕を、正面から「抑えてから詰める」（戦術の目録の T4、S7・S8）で取る。

- 仕様書：`docs/spec.md` の「ステージの作り直し：教程」の「教程2：抑えてから詰める（T4）」が正
- 地図：`maps/tutorial_2.json`（仕様側で作った。`Assets/StreamingAssets/maps/` にも同じものを置く）

## タスク

1. ステージの選び方に「教程2」を足す（教程1 の作りを使う）
2. 教程の通し実行に、教程2 の5作戦 × 20シード（任せる）を足す。教程1 と同じ表（勝率・損害率・崩した時刻・確保した時刻・崩れた中隊）。あわせて、R1 が制圧されていた秒数（B3 が地峡に入ってから着くまでの間）を出す
3. 線を満たさなければ、制限時間（25〜40分）だけを合わせてよい。それでも満たせなければ止めて報告

## テスト

- 単体テスト：教程2 の地図の読み込み（湖・地峡・配置・任務の文）
- 速いテストは .NET と Unity（バッチモード）の両方を回す。シナリオA と教程1 の結果が変わらないこと
- 教程の通し実行は Claude Code が回す。シナリオA の通し実行は回さなくてよい

## 完了基準と push の条件

- 速いテストが全て通り、教程2 が仕様の線を満たす（総員突撃・正面火力戦 0.3 以下、抑えてから詰める 0.8 以上、損害の比べ）
- 満たせば、`docs/reports/T2_report.md` を書いて commit し、タグを打って push する。制限時間を変えた場合は地図ファイルと報告に書く
- 満たさなければ止めて報告する

## スコープ

- 含める：上のタスクのみ
- 含めない：規則の値の変更、Sim の規則の変更、ほかの教程
- リファレンス実装は変更しない

## 方針

- 着手前の設計報告は不要。迷った点と自分で決めた点は報告に一覧で残す（特に、作戦の命令の作り方）
- 勝ち方が狙いどおりか（B3 が R1 の伏せている間に詰めて崩すか）を、会戦の経過で少なくとも3件確かめて報告に書く
- 返事と報告は日本語で書く
