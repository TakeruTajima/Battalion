# 実装依頼：大隊指揮RTS プロトタイプ T1（教程1：側面を突く）

## Git タグ

完了時に `proto-t1-flank` を打ち、push する（下の条件を満たしたとき）。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-r3-turning` まで完了）。

規則（R1〜R3）と赤の守り方（E1）が揃ったので、戦術を1つずつ教える小さなステージ（教程）を足していく。最初は「側面を突く」（戦術の目録の T1・T3）。脇の開いた塹壕の1個中隊を、青3個中隊で攻める。正面からは通らず、拘束して脇から撃てば崩れる。

- 仕様書：`docs/spec.md` の「ステージの作り直し：教程（2026-10-31）」が正
- 地図：`maps/tutorial_1.json`（仕様側で作った。`Assets/StreamingAssets/maps/` にも同じものを置く）

## タスク

1. 地図ファイルの読み込みを一般にする：`objective`（`trench_clear` と、今のシナリオA の村の奪取）、`headquarters`、`briefing`、予備のない守りの計画、村のない地図。シナリオA の地図は今のまま読めて、会戦のログが変わらないこと
2. 終わりの判定に `trench_clear` を足す（仕様の「勝ち」のとおり）
3. ステージの選び方に「教程1」を足し、開始時に任務の文を出す。戦闘詳報に、勝ち負け・崩した時刻・確保した時刻・青の損害
4. 教程の通し実行（新しいテスト。仕様の表の6作戦 × 20シード、任せる、崩れたら確保）。勝率・青と赤の損害率・崩した時刻と確保した時刻の中央値・崩れた中隊の表を出す
5. 線を満たさなければ、制限時間（35〜45分）だけを合わせてよい。それでも満たせなければ止めて報告

## テスト

- 単体テスト：地図の読み込み（教程・シナリオA）、`trench_clear` の判定（崩して確保・崩しただけで赤が戻る・赤が全て消える）
- 速いテストは .NET と Unity（バッチモード）の両方を回す。シナリオA のログの一致（Unity と .NET、前の版）が変わらないこと
- 教程の通し実行は Claude Code が回す。規則を変えないので、シナリオA の通し実行は回さなくてよい

## 完了基準と push の条件

- 速いテストが全て通り、教程の通し実行が仕様の線を満たす（総員突撃・正面火力戦 0.3 以下、拘束＋迂回の良い方 0.8 以上、損害と確保の時刻の比べ）
- 満たせば、報告（`docs/reports/T1_report.md`）を書いて commit し、タグを打って push する。制限時間を変えた場合は、地図ファイルと報告に書く
- 満たさなければ止めて報告する

## スコープ

- 含める：上のタスクのみ
- 含めない：規則の値の変更、ほかの教程、ヒントや教え方の表示（遊んでから決める）
- リファレンス実装は変更しない

## 方針

- 着手前の設計報告は不要。迷った点と自分で決めた点は報告に一覧で残す（特に、作戦の命令の作り方、確保の判定）
- 返事と報告は日本語で書く
