# 実装依頼：大隊指揮RTS プロトタイプ P2b（段階つき命令と信号弾）

## Git タグ

完了時に `proto-p2b-orders` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p2a-runners` まで完了）。

P2a を人が遊び、次の声が出た。

- 命令を1つしか持てないので、「丘を北から迂回して村へ向かえ」までは指示できても、その後は何もしない。遠くの中隊へは伝令で片道約11分かかるので、続きを出し直すのも難しい
- 伝令が、途上の敵陣をまっすぐ突っ切る

実際の作戦命令は「第1段：〜、第2段：〜」と段階に分けて書く。命令書を1人の伝令がまとめて運べば判断枠も節約でき、よく練った計画ほど伝令の負担が少なくなる。段階の切り替えの時機は、伝令を待たずに信号弾で合わせられる。これが H4（命令の遅れが読み合いを生む）の核心になる。

P2 の並びを変えた：P2b 段階つき命令（今回）、P2c 中隊長の自律行動、P2d 霧と報告。

- 仕様書：`docs/spec.md` の「P2b：段階つき命令と信号弾（確定）」が正

## タスク

仕様の P2b を実装する。

1. 段階つき命令（最大3段。移る条件は「完了したら」「時刻」「信号弾」。移る時に練度の遅れ。命令書は1人の伝令が運び、届いたら全て置き換える。会戦開始前の命令も段階つき）
2. 命令書の確認と修正（起案中・送付中・実行中の3つに分けて見せる。起案中は段の追加・削除・入れ替え・変更。「発令」を押したときに初めて出す。伝令が出発するまでは直す・取り消すことができ、取り消すと判断枠が空く）
3. 信号弾（赤・緑・白、各1回。本部から全中隊へ即座に。判断枠を使わない。赤には効果なし）
4. 到着予定（命令の下見に、各段階の到着予定時刻）
5. 伝令の経路（経路探索、脅威の重み 3.0、川は橋と浅瀬、10秒ごとに引き直し。到着予定と受領の強制開放の見積もりも経路の長さで）
6. 表示：
   - 命令書を組む画面（右パネルなど）。中隊ごとに起案中・送付中・実行中の命令書を並べ、起案中だけ編集できる。段階の追加・削除・上下の入れ替え、各段階の命令と移る条件の選択、「発令」「起案の破棄」。準備中の命令書には「直す」「取り消す」。選べない組み合わせの印。時刻の条件は分単位で増減できればよい
   - 段階ごとの経路と目的地の下見を、段階の番号つきで地図に出す（今の段階は濃く、後の段階は薄く）
   - 中隊の駒と左パネルに、今の段階（例：「2/3」）と次へ移る条件
   - 上部バーに信号弾の3色のボタン（使ったものは消える）。キーも割り当てる
   - 出来事の欄：「第2中隊 第2段へ（信号弾 緑）」「信号弾 緑」

パラメータ：新しい数値（段階の最大数、伝令の脅威の重み、伝令の経路の引き直しの間隔など）は `sim_params.json` に置く。キーは設計で提案する（仕様側で `sim_params.initial.json` に反映する）

## テスト

- 単体テスト：
  - 3段の命令書が、完了・時刻・信号弾のそれぞれの条件で順に進み、移る時に練度の遅れが掛かる
  - 保持・拘束の後の段階に「完了したら」は付けられない
  - 新しい命令書が届くと、古い命令書の残りの段階は全て消える
  - 準備中の命令書を取り消すと、伝令は出ず判断枠が空く。準備中に直すと、直した内容が届き、準備の残り時間は変わらない。出発後は取り消せない
  - 段の入れ替えで第1段になった段の条件が外れ、条件のない第2段・第3段は発令できない
  - 信号弾は各色1回だけ。判断枠を使わず、全中隊に即座に届く
  - 会戦開始前の段階つき命令が、伝令なしで届く
  - 伝令が射界を避けて回り込む（まっすぐより射界を通る時間が短い）。川を橋か浅瀬で渡る。動く中隊を追って経路を引き直す
  - 到着予定が、実際の到着時刻と大きくずれない（平地の前進で ±10% 程度）
- S1〜S6 は変わらない見込み。±15% 以内を確かめる
- 通し実行：今の作戦はそのまま（回帰の指標）。加えて「拘束＋迂回」を、段階つき命令と信号弾で組んだ版を足す（例：拘束役は第1段で遠い拘束、迂回役は第1段で北の待機地点へ前進・第2段で信号弾を条件に攻撃、全中隊の最後の段は村への前進。信号弾は迂回役が待機地点に着いた頃の時刻に打つ）。P2a と並べて報告する

## 完了基準

- Unity 6.3 LTS（6000.3.11f1）と .NET でテストが全て通る
- 通し実行の表と、大きく変わった作戦の理由が報告にある
- `Sim` が UnityEngine を参照しない
- 報告に、人が触って確かめる項目の一覧と、変わった操作の早見表を含める

## スコープ

- 含める：上のタスクのみ
- 含めない：中隊長の自律行動（P2c）、霧と報告（P2d）、作戦目標の評価（記録のみ）、電話線、砲兵（P3）以降
- 地図データとリファレンス実装は変更しない

## 方針

- **着手前に設計を短くまとめて報告し、返答があるまで実装に入らないこと。** 特に、命令書と段階の状態の持ち方（P2a の伝令・開始待ちとの関係）、「完了」の判定を命令ごとにどう決めるか、命令書を組む画面と操作（起案・発令・準備中の修正と取り消し。今の「選ぶと即発令」からの変わり方）、伝令の経路探索の置き場所と重さ、パラメータのキーを書く
- 仕様の解釈で迷ったら一覧に残し、もっとも素直な解釈を提案に含める
- Unity は 6.3 LTS（6000.3.11f1）で開く
- 完了したら止まって報告する。P2c には進まない
