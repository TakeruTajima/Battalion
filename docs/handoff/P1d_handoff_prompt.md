# 実装依頼：大隊指揮RTS プロトタイプ P1d（行動の規則）

## Git タグ

完了時に `proto-p1d-behavior` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p1c-feedback` まで完了）。

P1b・P1c を人が遊んで、中隊の動きに不自然な所が見つかった。

- 予備（R3）の逆襲が、決めた時点の目標の向きで側を選び、目標が向きを変えた後も反対側へ回ろうとして、目標の中をすり抜けた
- 敵の中隊と重なれる（P1 では衝突を扱わないと決めていたため）
- 拘束の命令が近づかないので、足止めにならない
- 攻撃で敵を崩した後に、追うか固めるかを命令できない
- 保持している中隊は、脇から撃たれても向き直らない
- 壊走した中隊が右往左往して、再集結に移れないことがあった

仕様の考え方は「プレイヤーは大隊長で、執行の細部は中隊長（性格）に任せる」。P1d は、その切り分けに沿って行動の規則をそろえる。

- 仕様書：`docs/spec.md` の「P1d：行動の規則（確定）」が正。数値もそこに書いてある

## タスク

仕様の「P1d：行動の規則（確定）」の1〜7を実装する。

1. 攻撃の側の選び直しと、着いた後の方角の固定
2. 敵の中隊と重ならない（止まる、経路で避ける、壊走中もすり抜けない、退路の見積もりでもふさがれた方位は逃げられない）
3. 拘束は 125m まで詰める
4. 追撃の許可（攻撃の命令の選択肢、性格ごとの判断、追う動き、限界、自動一時停止）
5. 向き直り（性格ごとの条件、練度の遅れ）
6. 壊走中の味方のすり抜けと、隊形の乱れ
7. 逃げる方位の揺れ止めと、右往左往の原因の調査

表示（View）：
- 攻撃の命令に「目標が崩れたら：確保／追撃可」を選ぶ操作を足す（右パネルのボタンとキー。初期は確保）
- 追撃中・向き直り中・隊形の乱れが分かる印を、P1c の行動の印と同じ系統で足す
- 自動一時停止に「攻撃の目標が崩れた」を足す

パラメータ：新しい数値は `sim_params.json` に置く。キーの名前と置き場所は設計報告で提案する（仕様側で `sim_params.initial.json` に反映する）

## テスト

- 1〜7それぞれの単体テスト（例：目標が90°向きを変えたら側を選び直す、着いた後は目標が回っても動かない、敵の矩形の手前で止まる、経路が敵を避ける、拘束が125mで止まる、性格ごとの追撃と向き直り、すり抜けた味方の士気と射撃、揺れ止め）
- S1〜S6 は v3 の正解値の ±15% 以内のまま（平地で全部隊が保持なので、向き直りが入ると変わりうる。変わったら理由を報告する。向き直りで S3・S4 の側面・背面の効果が消えるなら、テストの配置は「向き直らない」設定で回す案を報告に含める）
- 5作戦の通し実行（各20回）は、規則が変わるので結果が変わってよい。新しい表を P1c と並べて報告し、大きく変わった作戦は理由を調べる

## 完了基準

- Unity 6.3 LTS（6000.3.11f1）と .NET でテストが全て通る
- S1〜S6 の扱いが報告にある（そのまま通るか、テストの配置を変えた理由）
- 5作戦の新しい表と、P1c との違いの理由が報告にある
- `Sim` が UnityEngine を参照しない
- 報告に、人が触って確かめる項目の一覧と、変わった操作の早見表を含める

## スコープ

- 含める：上のタスクのみ
- 含めない：伝令・霧と報告・自律行動の残り（P2）、砲兵（P3）、敵AI（P4）、戦闘詳報（P5）、仕様の「保留」の3点
- 地図データとリファレンス実装は変更しない

## 方針

- **着手前に設計を短くまとめて報告し、返答があるまで実装に入らないこと。** 特に、向き直りと拘束・攻撃の命令の関係（どの命令の中隊が向き直るか）、敵の矩形との当たり判定の方法、パラメータのキー、S1〜S6 への影響の見込みを書く
- 仕様の解釈で迷ったら一覧に残し、もっとも素直な解釈を提案に含める
- Unity は 6.3 LTS（6000.3.11f1）で開く
- 完了したら止まって報告する。P2 には進まない
