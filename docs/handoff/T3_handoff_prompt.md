# 実装依頼：大隊指揮RTS プロトタイプ T3（教程3：砲撃に合わせて詰める）

## Git タグ

完了時に `proto-t3-barrage` を打ち、push する（下の条件を満たしたとき）。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p3-artillery` まで完了。仕様側の記録の変更が作業ツリーにあれば、最初の commit に含める）。P3 の砲兵で、砲撃と前進の連動（T17、S28）が効くようになった。それを教える3つ目の教程。教程2 と同じ地峡で、青は2個中隊と野砲 40発。

- 仕様書：`docs/spec.md` の「教程3：砲撃に合わせて詰める（T17、P3 の後。2026-11-01）」が正。P3 の結果の記録も足してある
- 地図：`maps/tutorial_3.json`（仕様側で作った。`Assets/StreamingAssets/maps/` にも同じものを置く）

## タスク

1. ステージの選び方に「教程3」を足す。会戦前に計画射撃点を登録できること（P3 の操作）
2. 教程の通し実行に、教程3 の6作戦 × 20シード（任せる）を足す。教程1・2 と同じ表に、砲撃が止んだ時の B2 と塹壕の距離、B2 が接近戦の距離に入った時刻（砲撃が止んでからの秒）、詰めるまでの B2 の損害を足す
3. 線を満たさなければ、制限時間（25〜40分）と弾数（32〜56発）だけを合わせてよい。それでも満たせなければ止めて報告

## テスト

- 単体テスト：教程3 の地図の読み込み（配置・砲兵・任務の文）
- 速いテストは .NET と Unity（バッチモード）の両方を回す。教程1・2 とシナリオA の結果が変わらないこと（規則を変えないので、シナリオA の通し実行は回さなくてよい）

## 完了基準と push の条件

- 速いテストが全て通り、教程3 が仕様の線を満たす（落ちる3作戦 0.3 以下、砲撃と前進の連動 0.8 以上、詰めるまでの損害の比べ）
- 勝ち方が狙いどおりか（砲撃が止んだ直後の隙に B2 が縁へ飛び込んで崩すか）を、会戦の経過で少なくとも3件確かめて報告に書く
- 満たせば `docs/reports/T3_report.md` を書いて commit・タグ・push。制限時間・弾数を変えたら地図と報告に書く。満たさなければ止めて報告

## スコープ

- 含める：上のタスクのみ
- 含めない：規則の値の変更、R5、霧、ほかの教程
- リファレンス実装は変更しない

## 方針

- 着手前の設計報告は不要。迷った点と自分で決めた点は報告に一覧で残す（特に、止む時刻の合わせ方、B1 の動き）
- 返事と報告は日本語で書く
