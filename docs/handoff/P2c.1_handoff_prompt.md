# 実装依頼：大隊指揮RTS プロトタイプ P2c.1（撃てる目標がないときの向き）

## Git タグ

完了時に `proto-p2c.1-fix` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p2c-autonomy` まで完了）。

P2c の報告の切り分けで、「撃てる目標がないときに最も近い既知の敵の方を向く」規則が、勝率低下のほぼ全ての原因と分かった。報告の案1・3・4を組み合わせ、「近い敵」ではなく「危ない敵」を向く規則に直す。案2（塹壕・村の守りは向かない）は場所で特別扱いするので採らない。

- 仕様書：`docs/spec.md` の「P2c.1：撃てる目標がないときの向きの直し（確定）」が正
- `sim_params.initial.json` は、P2c の `autonomy` の節を反映済み（今の `sim_params.json` と同じ）

## タスク

1. 向く相手の順位：
   - 直近 30秒に自分を撃った敵
   - 自分から見える 400m 以内の最も近い敵
   - 自分から見える 600m 以内の最も近い敵
   - いなければ今の向き
2. 「陣営のどれかから見える敵」をやめ、自分から見える敵にする
3. 正面の弧（±60°）の 400m 以内に、自分から見える敵がすでにいれば向き直らない
4. 撃てる目標ができたら、自律の向きを解いて命令の向きに戻す（その後は今どおり射撃と P1d の向き直り）
5. 通し実行に、B3（猪突）が「確保」の字面で攻撃する作戦を1つ足す（ステージ1・2。猪突の独断の出方を見るため）

パラメータ：新しい値（30秒など）は `autonomy` の節に置き、キーを報告に書く（仕様側で反映する）

## テスト

- 単体テスト：
  - 自分を撃っている敵が、より近い撃っていない敵より優先される
  - 正面の弧の 400m 以内に見える敵がいれば、別の敵の方へ向き直らない
  - 自分から見えない敵（味方からは見える）の方は向かない
  - 撃てる目標ができたら命令の向きに戻る
- S1〜S6 は ±15% 以内
- 通し実行：表を P2c（任せる・厳命）と並べる。P2c の報告で切り分けた3作戦（ステージ1の遠い拘束・近い拘束、ステージ2の総員突撃）は、向きの規則を止めた版の値とも並べる
  - 勝率を合わせる作り込みはしない。P2b.2 に戻らなくてもよい（守る側が回り込みに気付くのは正しい振る舞いでありうる）。戻らない作戦は、なぜそうなるかを書く
  - 新しい作戦の独断の回数も、P2c と同じ表に入れる
