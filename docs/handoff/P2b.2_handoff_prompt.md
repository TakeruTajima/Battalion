# 実装依頼：大隊指揮RTS プロトタイプ P2b.2（壊走・動揺と命令書）

## Git タグ

完了時に `proto-p2b.2-fix` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p2b.1-fix` まで完了）。

P2b.1 のプレイで2つ挙がった。

- 壊走中・再集結中の中隊に伝令を出せない（View の `CanCommand` が指揮下を条件にし、Sim も指揮下でない中隊に届いた命令書を捨てる）
- 再集結した中隊が、命令書に前進が残っているのに動かない

後者の原因（仕様側で確かめた）：`Simulation.cs` の再集結の完了で `c.CurrentOrder = Order.Hold(c.Id)` にしているが、`ActiveSheet` と `StageIndex` は前進の段のまま残る。表示と動きが食い違い、`StageComplete` の `ReferenceEquals(c.CurrentOrder, stageOrder)` が二度と満たされない。動揺で前進を保持に変える箇所（状態遷移の `want == CompanyState.Shaken`）も同じ作りで、正常に戻っても再開しない。

- 仕様書：`docs/spec.md` の「P2b.2：壊走・動揺と命令書（確定）」が正

## タスク

1. 壊走中・再集結中の中隊にも命令書を送れる。届いた命令書は預かり、指揮下に戻ったら練度の遅れの後に第1段を始める
2. 壊走した時点で実行中の命令書を中断する。再集結の後は、預かった命令書があればそれを、なければ命令待ち
3. 動揺で止まった段は「動揺で停止中」とし、正常に戻ったら練度の遅れの後に同じ目的地で再開する。動揺中に始まって拒まれた段も同じ
4. 表示：「命令書を預かり中（再集結後に開始）」「動揺で停止中」、出来事の欄「壊走（命令書は中断）」。命令待ち（P2b.1）の判定も、この規則に合わせる

## テスト

- 単体テスト：
  - 再集結中の中隊に送った命令書が、指揮下に戻ってから練度の遅れの後に始まる
  - 壊走で命令書が中断され、再集結の後は命令待ちになる
  - 動揺で止まった前進が、士気50超に戻ると練度の遅れの後に再開し、着けば「完了したら」が満たされる
  - 動揺で停止中でも、時刻・信号弾の条件で次の段へ移れる
- S1〜S6 は ±15% 以内
- 通し実行：規則が変わるので結果は動く。表を P2b.1 と並べ、大きく変わった作戦の理由を書く（回帰の指標。作り込みはしない）

## 完了基準

- Unity 6.3 LTS（6000.3.11f1）と .NET でテストが全て通る
- 通し実行の表と、大きく変わった作戦の理由が報告にある
