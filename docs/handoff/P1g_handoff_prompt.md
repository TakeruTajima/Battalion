# 実装依頼：大隊指揮RTS プロトタイプ P1g（目標が見えないときの中隊長の判断）

## Git タグ

完了時に `proto-p1g-sight` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p1f-terrain-view` まで完了）。

P1e のプレイで、攻撃を命じた中隊が発起点に着いたのに、稜線で目の前の敵が見えずに黙って立っていた。P1f の断面図（`docs/reports/P1f/terrain_r1_dead_ground.png`）で、ステージ1の R1 から 250m の発起点が死角に入ることが確かめられている。

「指示された位置で、敵が見えないから撃てずに黙って見ている」は中隊長としておかしい。命令の目的に沿って、中隊長が見える所を探すようにする。

- 仕様書：`docs/spec.md` の「P1g：目標が見えないときの中隊長の判断（確定）」が正

## タスク

仕様の P1g の各項目を実装する。

1. 攻撃：発起点で目標が見えなければ、固定した方角に沿って見えて射程内になるまで詰める
2. 拘束：拘束点で見えなければ、距離を保って左右 ±45° に見える位置を探す。なければ詰める（125m より近くへは詰めない）
3. 接触中は視線を問わない（矩形の隙間 50m 以内）
4. 見える位置を探して動いたことを、ログと下部の出来事の欄に出す
5. 表示：見える位置を探して動いている中隊に、P1c の行動の印と同じ系統の印を出す

パラメータ：新しい数値（±45°、50m の接触の距離など）は `sim_params.json` に置く。キーを報告で提案し、仮に足して進めてよい（仕様側で `sim_params.initial.json` に反映する。反映までは同一性のテストが落ちてよい）

## テスト

- 単体テスト：
  - ステージ1で、R1 の死角にある発起点に着いた攻撃の中隊が、見えるまで詰めて撃ち始める
  - 拘束の中隊が、死角の拘束点から左右に見える位置を探して移る。範囲に見える位置がなければ詰める
  - 隙間 50m 以内なら、視線が通らなくても撃ち合う
  - 保持の中隊は、見えない敵がいても動かない
- S1〜S6 は v3 の正解値の ±15% 以内のまま（平地なので変わらない見込み）
- 通し実行の表を P1f と並べて報告する（回帰の指標。勝率を合わせる作り込みはしない）
