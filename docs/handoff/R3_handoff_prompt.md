# 実装依頼：大隊指揮RTS プロトタイプ R3（向き直りの速さ）

## Git タグ

完了時に `proto-r3-turning` を打ち、push する（下の条件を満たしたとき）。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-e1-defense` まで完了）。

戦術の目録（`docs/design/tactics.md`）の C1 の残りの穴。接敵中でも旋回が毎秒 6°（90° に 15秒）と速く、拘束のない1個中隊の回り込みが 36秒で向き直られて効かない（S11 0.60）。正面 200m の線を組み直すには、端の兵が歩いて約 130秒かかる。

- 仕様書：`docs/spec.md` の「R3：向き直りの速さ（確定）」が正

## タスク

1. 接敵中の旋回の速さを `movement.turn_deg_per_sec_engaged`（0.69）にする。接敵していないときは今の 6° のまま。対象は仕様のとおり（壊走は対象外）
2. 接敵中にその場で 20° を超えて向きを変えている間は、R1 の「動いている」扱い（被弾 ×3.0・撃つ力 ×0.3・制圧のしきい値）。`movement.turning_counts_as_moving` で入り切り
3. 表示：「今効いている倍率」に「旋回中（動いている扱い）」
4. 期待を判定するテスト（S10〜S13 の期待を仕様の値に、S1〜S9・S14〜S19 は変わらない・満たし続ける）。満たさなければ仕様の掃き出し
5. 通し実行を回し、E1 の値と並べる

パラメータ：2つを `sim_params.json` に足し、決まった値で `docs/reference/sim_params.initial.json` にも反映してよい（今回は Claude Code が反映する）

## テスト

- 単体テスト：接敵中・接敵していない時の旋回の速さ、旋回中の動いている扱い（20° 以下では掛からない）、入り切り、壊走は対象外
- 速いテストは .NET と Unity（バッチモード）の両方を回す。通し実行（`ScenarioAReportTests`）も Claude Code が回す
- S1〜S6 の v4 照合、ログの一致を見るテスト（規則を止めた値で前の版と一致）が通ること

## 完了基準と push の条件

- 速いテストが全て通り、S10〜S13 の期待を満たし（掃き出しで選んだ場合はその値で）、S1〜S9・S14〜S19 が変わらない・満たし続ける
- 通し実行で、拘束＋迂回（良い方）が両ステージで 0.6 以上
- 上を満たせば、報告（`docs/reports/R3_report.md`）を書いて commit し、タグを打って push する。0.15 以上動いた作戦は、報告に会戦の経過で原因を書く（それだけでは止めない）
- 満たさなければ、止めて報告する

## スコープ

- 含める：上のタスクのみ
- 含めない：正面の弧の外を撃つ ×0.5 の見直し、隊形、P2d、ステージの作り直し
- 地図データとリファレンス実装は変更しない

## 方針

- 着手前の設計報告は不要。迷った点と自分で決めた点は報告に一覧で残す（特に、移動中の旋回と「その場で」の旋回の区別、自律の向きの直しが遅くなることの影響）
- 返事と報告は日本語で書く
