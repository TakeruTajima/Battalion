# 実装依頼：大隊指揮RTS プロトタイプ P1b（Unity での表示と操作）

## Git タグ

完了時に `proto-p1b-view` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p1a.1-params` まで完了）。

P1b は、初めて人が触る段階。目標は「シナリオAで4中隊を動かし、地形を読んで攻め方を選べる」こと。ここで H1（包囲と砲撃の手応え。砲撃は P3）と H3（正面は高くつき、側面は速い）を、数字ではなく手触りで確かめる。

**見た目は最低限でよい。** 絵は作らない。軍隊符号と図形、色分けしたマスだけで描く。判断に必要な情報が読めることを優先し、凝った演出はしない。

- 仕様書：`docs/spec.md`（「UIと戦闘詳報」「P1 詳細仕様」の「Sim と表示の境界（P1b）」と「完了基準」）
- Sim：`Assets/Sim`（UnityEngine を参照しない。この方針は崩さない）
- 地図：`maps/scenario_a1.json`、`maps/scenario_a2.json`
- 地図の見本：`docs/reference/map/scenario_a1_preview.png`、`_a2_preview.png`（色分けと等高線の参考）

## タスク

0. **Unity で開けるか確かめる（P0 からの持ち越し）**
   - Unity 6.3 LTS のエディタがこの PC にあるか探す（Unity Hub の既定のインストール先など）。あれば `-batchmode` でプロジェクトを開いてコンパイルし、EditMode テスト（Sim.Tests）を実行する
   - なければ止まって報告する。人が手で開いて確かめる
   - コンパイルエラーや、.NET では通って Unity で落ちるテストがあれば、P1b に入る前に直して報告する

1. **表示用のアセンブリ**：`Assets/View`（`Battalion.View`）を作り、Sim を参照する。Sim 側に UnityEngine を持ち込まない
2. **起動と読み込み**：1つのシーン。起動時にステージ1か2を選ぶ（簡単なボタンでよい）。`StreamingAssets` の `sim_params.json` と地図を読む。地図ファイルを `StreamingAssets` に置くか、既存の `maps/` から読むかは設計で決める
3. **時間**：仕様どおり（ゲーム内秒＝現実の秒×4×倍速、1フレーム最大16刻み）。スペースで一時停止、倍速は×1／×2／×4。一時停止中も命令を出せる（P1 では即時に適用）
4. **地図の描画**：地形の色分け、等高線（標高5m おき程度）、村・森・川・橋・浅瀬・塹壕が見分けられること。カメラの移動（ドラッグかキー）と拡大縮小
5. **駒の描画**：200m×50m の矩形（実寸）。味方は青、敵は橙、歩兵は×印。向き、兵力、士気、状態（正常・動揺・壊走・再集結・降伏）が読めること。表示は直前の2刻みの間を補間する
6. **命令の入力**：中隊を選ぶ（クリック、または1〜4）→ 命令を選ぶ（右パネルのボタンとキー）→ 地図をクリック。ドラッグで到着後の向きを指定
   - 前進・後退・保持・拘束・攻撃・陣地構築
   - 攻撃は目標の敵中隊と方向（指定なし／正面／側面／背面）を選べること
   - 選んだ中隊の経路と目的地を表示する
7. **画面構成**：仕様の「画面構成」のうち、P1 で必要なものだけ
   - 上部バー：経過時間、一時停止と倍速
   - 左パネル：中隊の一覧（性格、練度、兵力と士気のバー、現在の命令、状態）
   - 右パネル：選んだ中隊の詳細と命令ボタン
   - 下部：ログ（壊走、降伏、包囲、再集結、予備隊の逆襲などの主な出来事を時刻つきで）
   - 判断枠・砲弾・伝令・霧・報告は P2 以降なので作らない。P1 では敵は全て見えている
8. **視線確認ツール**：地図上の地点（または敵中隊）を選ぶと、そこから見えるマスを重ねて表示する。Sim の `LineOfSight` を使い、表示側で視線を計算し直さない
9. **会戦の終わり**：90分、または勝ちの判定（仕様の「P1a の設計で確定した細則」）で止め、勝敗と主な数字（双方の損害、崩れた中隊、降伏）を出す。戦闘詳報は P5 なので作らない
10. **調整用の切り替え**（プレイテスト用）
    - `sim_params.json` の `terrain.moving_open_damage_mult`（初期値 1.0）を Sim に足す：平地・砲撃痕・橋・浅瀬を移動中の中隊は、被弾にこの値を掛ける。1.0 なら今の挙動と完全に同じであること（全テストとログの一致で確かめる）
    - デバッグ表示（キーで切り替え）：露出の地図（陣営ごと）、予備隊の台本の引き金の円、各中隊の退路の見積もり（最小の方位と損害）

## 完了基準

- Unity 6.3 LTS でプロジェクトが開け、コンパイルが通り、EditMode テストが全て通る（.NET でも従来どおり通る）
- 再生すると、ステージを選んでシナリオAが始まり、タスク3〜10ができる
- `Sim` アセンブリが UnityEngine を参照していない
- `moving_open_damage_mult` が 1.0 のとき、S1〜S6 と5作戦の通し実行の結果が P1a.1 と完全に同じ
- 報告に、人が触って確かめる項目の一覧（チェックリスト）と、操作の早見表を含める。動作は人が確かめるので、あなたが確かめられた範囲と、確かめられなかった範囲を分けて書く

## スコープ

- 含める：上のタスクのみ
- 含めない：伝令の遅延・判断枠・霧と報告・自律行動（P2）、砲兵（P3）、敵AI（P4）、戦闘詳報（P5）、立ち絵・効果音・演出
- 地図データ・リファレンス実装は変更しない。Sim の挙動は、`moving_open_damage_mult` の追加と、表示に必要な読み取り用の口だけにとどめる

## 方針

- **着手前に設計を短くまとめて報告し、返答があるまで実装に入らないこと。** まとめる内容：Unity の確認結果（タスク0）、View の構成（Sim の状態の読み方と補間、時間の進め方）、描画の方法（地形をテクスチャ1枚で描くか等）、入力の流れ、UI の作り方（uGUI か UI Toolkit か）、視線確認ツールの計算量
- Unity で開けない場合は、タスク0の段階で止まって報告する
- 仕様の解釈で迷ったら一覧に残し、もっとも素直な解釈を提案に含める
- 完了したら止まって報告する。P2 には進まない
