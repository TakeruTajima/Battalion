# 実装依頼：大隊指揮RTS プロトタイプ R1（開けた所を動く代償と制圧）

## Git タグ

完了時に `proto-r1-suppression` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-v1-objectives` と報告のコミット 13ee0bc まで完了）。

P2c のプレイと V1 の通し実行で、ステージ2 は「全中隊に村への前進だけ」で第一目標 0.95 を取れた。塹壕の射界を横切っても、損害がほとんど出ないためだ。

史実では、陣地の小銃兵に開けた所を進むと大損害が出る（1870年のサン・プリヴァでは、プロイセン近衛軍団が20分足らずで8,000人を超える損害を出したとされる）。撃たれた歩兵は伏せて前進が止まるのが普通で、攻める側は火力で抑えてから詰めた。

今の Sim には、そのどちらもない。
- 1個中隊が1個中隊に与える損害は毎分約 2人で、両方が伏せて撃ち合う火力戦に合わせた値。立って進む兵にも同じに効く
- 撃たれて止まる仕組みがない

避けたいのは「本来、攻める側がかなり工夫しなければ勝てない陣地に、突撃だけで勝ててしまう」誤った釣り合い。弱い守りのステージが突撃で破れるのは構わない。そこで値はステージではなく、強い陣地の検証の場面 S7〜S9 で確かめて決める。

- 仕様書：`docs/spec.md` の「R1：開けた所を動く代償と制圧（確定）」が正。背景は「Battalion への課題：P2c のプレイと史実からの見直し」

## タスク

1. 検証の場面 S7〜S9 を、S1〜S6 と同じ形の単体の場面として作る（平地、塹壕のマスを置く）。期待（仕様の表）を満たすかを判定するテストにする
2. 規則1：開けた所を動く中隊の被弾倍率（`terrain.moving_open_damage_mult`）を、伏せて止まっている間は掛けないようにする
3. 規則2：制圧
   - 受けている火力の量（守りを除いた損害の式の和）
   - 姿勢で変わるしきい値と揺れ止め
   - 効き目：動いている中隊は伏せて止まり、解けたら続ける。撃つ力 ×0.5。自律行動の移動をしない
   - 性格の差
   - 接触の距離では止まらない
4. 値を決める：S7〜S9 の期待を満たす `moving_open_damage_mult` と、制圧のしきい値の組を探す（候補を数通り回す短い掃き出し）。満たす組がなければ、一番近い組と、どの期待が満たせないかを報告する
5. S1〜S6：変わるかどうかを設計報告で見積もる。変わる場合、リファレンス実装（`docs/reference/combat_reference.py`）の v4 は**仕様側で作る**（C# とは別に作った実装で突き合わせることに意味があるため。`docs/reference/**` は今までどおり変更しない）。仕様側が v4 の正解値を `reference_results.json` に入れた後、C# がその ±15% 以内に入ることを確かめる
6. 表示：「伏せ」の印、出来事の欄、中隊の詳しい表示の火力の量としきい値

パラメータ：新しい値は `sim_params.json` に置き、キーを設計で提案する

## テスト

- 単体テスト：
  - 制圧の始まり・終わり（揺れ止め）
  - 動いている中隊が伏せて止まり、解けたら同じ段のまま動きを続ける
  - 伏せている間は規則1 の倍率が掛からない
  - 撃つ力 ×0.5
  - 猪突・慎重のしきい値の差
  - 接触の距離では止まらない
  - 制圧下は物陰へ寄らない
- S7〜S9 の期待を満たす（決めた値で）。S1〜S6 は今の正解値か、仕様側が作り直した v4 の正解値の ±15% 以内
- **長い計算は回さない**：Claude Code が回すのは、速いテストと、S7〜S9 の短い掃き出し（平地の小さな場面なので数分の見込み。長くなるなら回し方を書いて止まる）だけ。シナリオA の通し実行は Takeru がローカルで回すので、回し方を報告に書く。通し実行では、特に「村への前進（全中隊）」と「総員突撃」の目標の達成率が、V1 の値からどう変わるかを見たい
