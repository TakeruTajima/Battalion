# 実装依頼：大隊指揮RTS プロトタイプ P2b.1（命令書の操作と命令待ちの表示）

## Git タグ

完了時に `proto-p2b.1-fix` を打ち、push する。

## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p2b-orders` と仕様の反映 513500b まで完了）。

P2b を人が遊び、評価は「かなり良い」。細かい声が3つ出た。

- 段を毎回［段を足す］で足すのが手間。足しただけで命令の入っていない段があると発令できないのも邪魔
- 命令を受けていない（または命令を終えた）中隊が、見て分からない
- 信号弾が効かない時機はないか。使った色を後の命令書に書くとどうなるか

- 仕様書：`docs/spec.md` の「P2b.1：プレイの声を受けた直し（確定）」が正

## タスク

1. 段の自動追加：起案中の段に命令を書き込んだら、その下に空の段を1つ自動で足す（3段まで）
2. 空の段は無視して発令：命令の入っていない段は条件が未設定でも発令を止めない。発令時に落として詰める
3. 命令待ちの表示：命令書がない中隊と、最後の段を終えた中隊に、駒の印・左パネル・出来事の欄で「命令待ち」を出す（保持・拘束は当たらない）。Sim に読み取りの口（中隊が命令待ちか）を置く
4. 使った色の信号弾：上がった色は起案の条件に選べなくする。起案中・準備中の命令書に使った色の条件が残っていれば印を出し、発令・差し替えを止める

## テスト

- 単体テスト：
  - 空の段を含む命令書が、空の段を落として発令される（間の空の段も詰める）
  - 命令の入った段に条件がなければ、今どおり発令できない
  - 命令待ち：会戦開始前は全中隊が命令待ち。前進の最後の段に着くと命令待ちになる。保持・拘束の段では命令待ちにならない。新しい命令書が始まると解ける
  - 使った色を条件に持つ命令書は、検査で発令できない
- 通し実行のログ（28通り）の SHA256 が P2b と一致すること（Sim の規則は変えない。命令待ちは読み取りだけ）

## スコープ

- 含める：上のタスクのみ
- 含めない：信号弾の撃ち直し、中隊長の自律行動（P2c）、霧と報告（P2d）
- 地図データとリファレンス実装は変更しない
