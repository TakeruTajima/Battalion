## 背景

リポジトリ：`TakeruTajima/Battalion`（`proto-p1e.2-fix` まで完了）。

P1e を人が遊んだ結果、操作は大きく改善した（攻撃の方角を示すと途中の経路が出るので、「丘を迂回して北から攻めよ」と同じ指示になる）。一方で、次の声が出た。

- 目の前の敵中隊を撃たない場面がある。おそらく稜線で視線が切れている
- 等高線に標高の情報がなく、立体が把握できない。「なぜか視線の通らない所がある」「なぜか目の前の敵を撃たない」になっている

**Sim の規則は正しく動いている。足りないのは、地形の高さと、視線が切れている理由の見せ方。** P1f は表示だけを足し、2D の地図のまま立体と死角を読めるようにする（3D 化はしない）。H2（負けた理由が分かる）と「教えるのではなく気付かせる」の土台になる。

- 仕様書：`docs/spec.md` の「P1f：地形の高さを読む」が正
- 地図の見本：`docs/reference/map/scenario_a1_preview.png`（陰影は付いていない。色分けの参考）

## タスク

仕様の「P1f：地形の高さを読む」のア〜オ。

- **ア：陰影（ヒルシェード）**：北西（方位315°、高度45°）から光を当てた陰影を、地形のテクスチャに掛ける。標高は Sim と同じ `TerrainMap` の値を使う。陰影は色分け（森・村・川など）を消さない程度に
- **イ：高さで色を変える＋等高線の数字**：平地の色を標高で明暗に変える（低いほど濃く、高いほど明るく）。25m おきの太い等高線に標高の数字を入れる（読める間隔で間引いてよい）
- **ウ：カーソルの位置の標高**：上部バーに、カーソルの地点の標高（m）を出す
- **エ：撃たない理由**：射程内（400m）に指揮下の敵がいるのに、視線が通らずに撃てていない中隊について、その敵へ点線を引き、線の中ほどに理由（「稜線」「森」「村」）を出す。選んでいる中隊は常に、それ以外はデバッグ表示と同じキーで切り替え（初期は選んだ中隊だけ）。理由は Sim の `LineOfSight` の結果（`ridge`・`cover`）を使い、表示側で計算し直さない
- **オ：断面図**：視線確認ツール（L）を拡張する。視線確認の状態で2点目を指定すると（例：Shift＋クリック、または駒から駒へのドラッグ。決め方は任せる）、その2点の間の地形の断面を小窓に出す
  - 横軸は距離、縦軸は標高（縦は誇張してよい。倍率を表示する）
  - 目の高さ（+2m）の視線の直線を重ね、遮られる区間を赤く示す
  - 森・村の区間を帯で示す（遮る重みが分かるように）
  - 計算は Sim の `LineOfSight` と同じ刻み（10m）と補間（双線形）を使う

## Sim への変更

- 表示のための読み取り専用の口だけ足してよい（例：視線の判定で、遮った位置と理由を返す）。会戦の結果を変えてはいけない
- 確認：P1e.2 と同じ通し実行のログ（17通り以上）の SHA256 が一致すること

## 完了基準

- Unity 6.3 LTS（6000.3.11f1）と .NET でテストが全て通る
- 通し実行のログが P1e.2 と完全に一致する
- バッチモードの画像で、陰影・高さの色・等高線の数字・撃たない理由の点線・断面図が描けていることを自分で確かめ、その画像を `docs/reports/P1f/` に置く。特にステージ1で、頂上の塹壕（R1）の目の前の斜面が死角になる様子が、陰影と断面図で読めること
- 報告に、人が触って確かめる項目の一覧と、変わった操作の早見表を含める

## スコープ

- 含める：上のタスクのみ
- 含めない：3D 化・斜め見下ろしのカメラ、Sim の規則と数値の変更、伝令・霧と報告（P2）以降
- 地図データとリファレンス実装は変更しない

## 方針

- 表示だけの変更なので、**着手前の設計報告は不要**。そのまま進めてよい。迷った点と、自分で決めた見た目の選択は報告に一覧で残す
- 情報を増やすと画面がうるさくなる。陰影・色・数字は控えめにし、駒・射撃線・行動の印が埋もれないようにする
- Unity は 6.3 LTS（6000.3.11f1）で開く
- 完了したら止まって報告する。P2 には進まない
